# 2~10차시 실습 자료 전면 재검토 기록 (2026-09-18)

이 문서는 2026-09-18에 진행한 2~10차시 실습 자료 재검토·재작성 작업의 전체 과정과 근거를 남긴 기록입니다. "무엇을 왜 바꿨는지", "무엇을 실제로 실행해서 확인했는지"를 나중에 다시 찾아볼 수 있도록 차시별로 정리했습니다.

## 0. 작업 배경과 원칙

사용자가 이번 검토에 앞서 정한 우선순위 원칙(그대로 적용함):

1. **실습 파일(`labs/ChNN-실습.md`)이 우선**이다. 강의안이 아니라 실습 파일이 실제로 손으로 따라 할 수 있는 기준 문서가 된다.
2. 실습 내용은 **차시별 강의안(`lect/CH-NN-Content.md`)을 참고**해서 검토한다 — 강의안과 실습이 다루는 개념·소주제 순서가 어긋나지 않아야 한다.
3. 실습이 강의안보다 우선하되, 필요하면 강의안을 참고할 수 있도록 각 실습 문서에 강의안의 소주제·페이지 번호를 명시한다.
4. 앞으로 새로 만들거나 수정하는 실습 파일은 전부 **`labs/` 디렉토리**에 둔다.

이 원칙에 따라 기존 루트 디렉토리의 `Ch02-실습.md` ~ `Ch10-실습.md` 9개 파일을 전부 `git mv`로 `labs/`로 옮기고, 각 파일을 처음부터 다시 작성했습니다(단순 이동이 아니라 구조와 검증 방식을 전면 개편).

## 1. 무엇을 바꿨는가 (전체 공통 변경사항)

기존 실습 문서는 강의(PPT) 자료의 "페이지 N, 실습 절차 1/2/3" 구조를 그대로 따르고 있었습니다. 이번 재작성에서는 다음과 같이 바꿨습니다.

- **PPT 슬라이드 구조 → 실행 단계(0단계, 1단계, ...) 구조**로 전환. 각 단계는 "실행할 코드 → 실제 실행 결과 → 확인할 점"의 3단 구성을 따릅니다.
- **파일 기반 체인 연결 도입**: 2차시 12단계에서 `data/processed/press_data.json`을 생성하고, 3차시부터 10차시까지 이 파일을 계속 불러오고(`json.load`) 필드를 추가해 다시 저장(`json.dump`)합니다. 예전에는 "이전 차시 결과를 이어받는다"는 서술만 있고 실제로 파일이 남지 않았습니다. 이제는 차시마다 실제로 갱신되는 파일 하나가 눈에 보이는 산출물로 남습니다.
- **모든 문서 상단에 "이 실습으로 만들어지는 것" 절 추가**: 사용자의 요청("모든 차시에서 실습을 통해 만들어질 것을 구체적으로 문서에 넣어서")에 따라, 파일 경로·JSON 필드·이미지 파일 등 구체적인 산출물을 각 문서 맨 위에 명시했습니다.
- **LLM 호출 단계에 비용·비결정성 안내 추가**: 4·7·8·9·10차시처럼 실제 Claude API를 호출하는 단계에는 "실제 비용 발생" 표시와 "예시 실행 결과이며 표현은 매번 달라질 수 있다"는 안내를 넣었습니다(과거 `REVIEW_Ch02-10.md`가 지적했던 누락 사항).
- **상대 경로 수정**: 파일이 `labs/`로 한 단계 내려가면서 `modules/`, `tests/`, `lect/` 등을 가리키는 모든 마크다운 링크에 `../`를 붙였습니다.
- **강의안 교차 참조 추가**: 각 단계 제목 옆에 `lect/CH-NN-Content.md`의 소주제·페이지 번호를 표시해, 개념이 헷갈릴 때 바로 찾아갈 수 있게 했습니다.

## 2. 검증 방법

문서에 적은 "실제 실행 결과"는 전부 **이번 세션에서 직접 실행해 확인**했습니다(예외: 아래 "실행하지 않은 것" 참고). 사용한 명령:

```bash
myvenv/Scripts/python.exe -c "..."   # 각 단계 코드 스니펫을 실제로 실행
pytest tests/ -v                      # 전체 단위 테스트
```

**최종 결과: 75개 테스트 전부 통과** (`tests/` 전체, `test_practice_*` 포함).

**실행하지 않은 것과 이유**: `generate_summary`, `generate_headline_set`, `generate_body_paragraphs`, `unify_style`, `review_press_release` 등 실제 Claude API를 호출하는 함수는 이번 검토에서 **직접 호출하지 않았습니다** — 사용자의 `ANTHROPIC_API_KEY`로 실제 과금이 발생하는 작업이라, 명시적 요청 없이 반복 실행하는 것은 피했습니다. 대신:
- 프롬프트를 조립하는 부분(`build_summary_prompt`, `build_headline_prompt` 등)은 API 호출 없이 실제로 실행해 검증했습니다.
- 응답을 받은 뒤 처리하는 부분(`parse_json_response`, `verify_numbers`, `check_formatting_errors`, `cross_check_all_numbers`)은 가짜 응답 문자열을 직접 만들어 실제로 실행해 검증했습니다.
- 실제 LLM 응답 예시는 기존 문서(이전 세션에서 실제로 API를 호출해 검증했다고 명시된 값)를 재사용하되, "예시 실행 결과 — 표현은 달라질 수 있음"이라고 명확히 표시했습니다.

## 3. 검토 중 실제로 발견한 문제 (이번 세션에서 새로 찾은 것)

기존 `REVIEW_Ch02-10.md`(2026-09-10 작성)가 지적한 A-1(역대최대 미자동화)·A-2(감소 케이스 해석문 누락)·A-3(NLP/요약 결과 단절)·Ch06 line차트 고아 기능은 **이미 모두 코드에서 수정되어 있음을 확인**했습니다(`modules/stats.py`의 `derive_history_indicators`, 감소 템플릿, `modules/charts.py`의 월별이력 분기, `main.py`의 `generate_summary` 호출 등). 이번 세션에서는 여기서 한 걸음 더 나아가, 실제로 코드를 실행하며 다음을 새로 발견했습니다.

## 5. 남은 과제 (이번 검토 범위 밖)

다음은 실습 문서에는 정직하게 기록해 두었지만, 이번 작업(문서 재검토)의 범위를 벗어나 코드 자체는 고치지 않은 항목입니다. 실제 라이브러리 코드 수정이 필요하면 별도 작업으로 진행해야 합니다.

- `modules/stats.py`의 지표명 자동 추출(`제목.split()[-1]`)이 "~동향"으로 끝나는 제목에서 어색한 문장을 만드는 문제
- AI가 본문에서 파생 수치(예: 비중 합계)를 스스로 계산해 넣을 때 `cross_check_all_numbers`가 이를 잡아내기는 하지만 자동으로 고쳐주지는 않는 문제 — 근본 해결은 `stats.py`가 해당 파생 수치까지 미리 계산해 `계산지표`에 넣어주는 것
- `modules/charts.py`의 `generate_table_description`이 여전히 `build_visual_descriptions`에서 호출되지 않는 별도 함수로 남아있음
