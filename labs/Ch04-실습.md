# Ch 04 실습. LLM 기반 텍스트 요약 실습

> 이 문서는 강의(PPT) 자료가 아니라, 직접 손으로 따라 하는 실습 가이드입니다. **실습은 이 문서를 기준으로 진행**하고, 개념 설명이 더 필요할 때만 강의안을 참고하세요.
> - 개념 설명(강의안): [../lect/CH-04-Content.md](../lect/CH-04-Content.md)
> - **실행 위치**: 모든 명령어는 프로젝트 루트 폴더에서 실행합니다.
> - **사전 준비**: [data/processed/press_data.json](../data/processed/press_data.json)에 `NLP분석결과` 필드가 있어야 합니다(3차시 7단계 완료 필요). `.env`에 `ANTHROPIC_API_KEY`가 설정되어 있어야 이 차시의 API 호출 단계를 실행할 수 있습니다.
> - **비용 안내**: 이 차시부터는 실제 Claude API를 호출하는 단계가 등장합니다. API 호출은 `.env`의 `ANTHROPIC_API_KEY`로 과금됩니다. 아래 2단계는 실제로 실행할지 여부를 직접 판단하세요(비용은 문장 몇 줄 생성 수준으로 매우 작지만, 0원은 아닙니다).
> - **비결정성 안내**: `temperature > 0`인 LLM 호출은 같은 입력을 다시 넣어도 매번 문장이 달라질 수 있습니다. 아래 "예시 실행 결과"는 실제로 한 번 실행해 확인한 값이지만, 여러분이 실행한 결과와 표현이 달라도 정상입니다 — 확인해야 할 것은 표현이 아니라 **숫자와 사실관계가 원본과 일치하는지**입니다.

## 실습 목표

- 역할·맥락·출력형식·제약조건 네 가지를 담은 요약 프롬프트를 설계한다.
- Claude API를 호출해 통계자료를 3줄 요약과 제목 후보로 생성한다.
- 생성된 문장 속 숫자를 원본 데이터와 자동으로 대조·검증한다.

담당 코드: [../modules/write.py](../modules/write.py)(요약 생성), [../modules/review.py](../modules/review.py)(수치 검증)
담당 테스트: [../tests/test_ch04_write.py](../tests/test_ch04_write.py)

## 이 실습으로 만들어지는 것

- [data/processed/press_data.json](../data/processed/press_data.json)에 **`요약결과`** 필드(`삼줄요약`, `제목후보`)가 추가된 버전
- 이 결과는 **참고용**입니다 — 7차시 헤드라인 생성 프롬프트에 "표현 아이디어"로만 전달되고, 새로운 숫자를 들여오지는 않습니다. 사실 확정은 5차시 계산 결과가 담당합니다([main.py](../main.py)의 실제 흐름과 동일).

```python
from modules.write import build_summary_prompt

prompt = build_summary_prompt(data)

```

**실제 실행 결과** (API 키 없이도 실행됩니다 — 문자열을 조립하기만 하는 함수이기 때문)

```
다음 자료를 참고하여 3줄 요약과 제목 후보 3개를 작성해 주세요.
계산지표: 총거래액 201250억 원, 전월대비 1.5% 증가,
전년동월대비 8.7% 증가
핵심키워드: 온라인쇼핑, 전월, 기록, 기준, 역대
주요문장: "2026년 1월 온라인쇼핑 거래액은 201,250억 원으로 전월 대비 1.5% 증가하였다."

결과는 반드시 아래 JSON 형식으로만 출력하십시오.
{"삼줄요약": ["문장1", "문장2", "문장3"], "제목후보": ["제목1", "제목2", "제목3"]}
```

이 프롬프트가 3차시의 `NLP분석결과`(핵심키워드, 주요문장)와 2차시의 `계산지표`를 그대로 이어받아 자동으로 채워졌는지 확인합니다.

## 2단계. Claude API 호출로 요약 생성하기 (실제 비용 발생)

> 개념 참고: 강의안 페이지 9, 12~13 (API 호출 기본 구조, JSON 출력 강제, 방어적 파싱)

```python
from modules.write import generate_summary

summary_result = generate_summary(data)
print(json.dumps(summary_result, ensure_ascii=False, indent=2))
```

**예시 실행 결과** (실제로 한 번 실행해 확인한 값 — 여러분의 결과는 표현이 다를 수 있습니다)

```json
{
  "삼줄요약": [
    "2026년 1월 온라인쇼핑 거래액은 201,250억 원을 기록하였다.",
    "이는 전월 대비 1.5%, 전년동월대비 8.7% 증가한 수치이다.",
    "역대 1월 기준 최대치를 달성하였다."
  ],
  "제목후보": [
    "1월 온라인쇼핑 거래액, 역대 최대 기록",
    "온라인쇼핑 거래액 8.7% 증가, 1월 최대치 경신",
    "1월 온라인쇼핑 동향, 거래액 역대 최고 수준"
  ]
}
```

`generate_summary()`는 1단계의 `build_summary_prompt()`로 프롬프트를 만들고, `client.messages.create()`로 API를 호출한 뒤, `parse_json_response()`로 결과를 파싱하는 과정을 하나로 묶은 함수입니다. `MODEL_NAME` 상수([modules/write.py](../modules/write.py) 최상단)는 이 차시부터 API를 호출하는 모든 함수(4·7·8·9차시)가 공유합니다.

## 3단계. 방어적 JSON 파싱 확인하기 (API 호출 없음)

> 개념 참고: 강의안 페이지 13 (모델 응답에 코드펜스나 설명이 섞여도 안전하게 파싱하기)

```python
from modules.write import parse_json_response

fake_response = '''여기 결과입니다:
```json
{"삼줄요약": ["문장1", "문장2", "문장3"], "제목후보": ["제목A", "제목B", "제목C"]}
```'''
print(parse_json_response(fake_response))
```

**실제 실행 결과**

```
{'삼줄요약': ['문장1', '문장2', '문장3'], '제목후보': ['제목A', '제목B', '제목C']}
```

실제 LLM 응답에는 "여기 결과입니다:"나 \`\`\`json 코드펜스 같은 부연 설명이 섞이는 경우가 실제로 많습니다. `parse_json_response`는 응답 전체를 그대로 파싱하지 않고, 처음 등장하는 `{`나 `[`부터 그와 짝이 맞는 마지막 닫는 괄호까지만 잘라내 파싱하므로 이런 설명이 섞여도 안전합니다.

## 4단계. 생성된 문장의 수치 자동 검증하기 (API 호출 없음)

> 개념 참고: 강의안 페이지 18 (verify_numbers로 환각 여부 자동 확인)

2단계에서 실제로 API를 호출했다면 그 결과로, 호출하지 않았다면 1단계의 예시 결과로 검증해봅니다.

```python
from modules.review import verify_numbers, find_unverified_numbers

for sentence in summary_result["삼줄요약"]:
    valid = verify_numbers(sentence, data)
    print(f"[{'통과' if valid else '재검토 필요'}] {sentence}")

# 일부러 원본에 없는 숫자를 넣어 검증 함수가 실제로 걸러내는지 확인
print("고의로 틀린 문장 검증:", find_unverified_numbers("거래액이 999999억 원을 기록했다.", data))
```

**실제 실행 결과**

```
[통과] 2026년 1월 온라인쇼핑 거래액은 201,250억 원을 기록하였다.
[통과] 이는 전월 대비 1.5%, 전년동월대비 8.7% 증가한 수치이다.
[통과] 역대 1월 기준 최대치를 달성하였다.
고의로 틀린 문장 검증: ['999999']
```

`find_unverified_numbers`가 원본에 없는 "999999"를 실제로 정확히 짚어내는 것을 확인합니다. 이 함수는 4차시뿐 아니라 9차시(전체 검수)에서도 동일하게 재사용됩니다.

## 완성도 점검

1. 세 문장 모두 수치 자동 검증(`verify_numbers`)을 통과하였는가
2. "압도적", "폭발적" 같은 과장되거나 단정적인 수식어가 포함되지 않았는가
3. 제목 후보 3개가 서로 다른 관점(수치 강조, 증감률 강조, 동향 강조)을 담고 있는가
4. `data/processed/press_data.json`에 `요약결과` 필드가 정상적으로 추가되었는가
