### 3-2. 강의 코드와 일부러 다르게 한 것

| 항목 | 강의 | 실습 | 이유 |
| --- | --- | --- | --- |
| 모델 | `claude-sonnet-4-5`("최신 ID로 교체" 안내) | `claude-sonnet-5-5` | 현재 최신 Sonnet |
| temperature | 0.2~0.4 권장(14) | 넣지 않음 | 최신 모델은 기본값 이외의 temperature를 400 오류로 거부. 개념 설명은 강의대로, 일관성은 제약 조건·Few-shot으로 |
| thinking | 없음 | `thinking={"type": "between_tools"}` | 추가 사고 없이 바로 답하게 해 강의 코드와 같은 동작·비용 |
| 응답 읽기 | `message.content[0].text` | `type == "text"` 블록만 모음 | 응답에 텍스트 외 블록이 섞여도 안전 |
| 비중 예시 | 의류 32.4%(9·13·18) | 32.3% | 이 데이터로 실제 계산한 값(65,000 ÷ 201,250). 보도자료에는 계산값만 사용 |

| PDF·HWPX | 텍스트 저장까지, 서식 변환은 "가볍게"(13) | 제공 파일 `export.py`를 복사해서 사용 | 공식 서식 변환은 실무 후처리 단계라 Claude Code로 만들지 않음 |

| server-side fallback | — | 쓰지 않음 | 강의의 `client.messages.create` 형태를 유지하기 위해(원하면 추가 가능) |

### 3-3. 새로 도입한 진행 장치

- **원자료 흐름**: 2차시 원본 JSON(월별이력 13개월·품목별 당월/전월 거래액 포함) → 7차시에 같은 원본으로 xlsx(요약·이력 시트)·PDF 생성 → 10차시는 xlsx 하나로 전체 실행. 모든 숫자가 서로 맞도록 설계(예: 이력으로 다시 계산한 전월대비 1.5%·전년동월대비 8.7%가 계산지표와 일치).
- **CLAUDE.md 누적 방식**: 2차시에 기본 규칙 5줄 + 공통 블록 + 2차시 블록으로 새로 만들고, 3차시부터는 차시 블록만 이어 붙임. 이미 있으면 건너뛰는 명령이라 **중복되지 않음**(옛 방식에서 공통 블록이 두 번 들어간 문제 해결).
- **LLM 차시의 검증은 가짜 응답**으로 구조만 확인(비용 0), 실제 호출은 권장 단계로 분리. 실제 호출을 건너뛰어도 다음 차시 "준비" 코드가 빠진 필드만 예시로 채움.
- **폴백·단독 시작**: 정답 코드(`solutions/chNN`)와 스냅숏으로 어느 차시에서든 시작·복구 가능.
- **실패 시 수정 요청 1회**: 검증 코드의 assert 메시지가 무엇이 틀렸는지 알려 주므로 그대로 Claude Code에 붙여 수정 요청.
