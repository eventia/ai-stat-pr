## 2. 입력 준비

이 차시는 `mywork/press_data.json`에 **`문서정보`, `계산지표`, `핵심내용`, `원문`** 필드가 있어야 합니다. 앞 차시를 그대로 진행했다면 이미 있고, 앞 차시를 건너뛰었다면 아래 스니펫이 **비어 있는 필드만** 채웁니다(이미 있는 값은 건드리지 않음).

```python
# 입력 Ch05
import json, os

NEED = json.loads("""{
  "문서정보": {
    "제목": "2026년 1월 온라인쇼핑 동향",
    "공표일자": "2026-03-01",
    "자료출처": "공공데이터포털 Open API"
  },
  "계산지표": {
    "총거래액": 201250,
    "전월대비증감률": 1.5,
    "전년동월대비증감률": 8.7
  },
  "핵심내용": [
    "온라인쇼핑 거래액 역대 최대 달성"
  ],
  "원문": "2026년 1월 온라인쇼핑 거래액은 201,250억 원으로 전월 대비 1.5% 증가하였다. 전년동월대비로는 8.7% 증가한 수치이다. 이는 역대 1월 기준 최대치를 기록한 것이다. 모바일쇼핑 거래액 비중은 전체의 78%를 차지하며 꾸준한 증가세를 보이고 있다."
}""")

os.makedirs("mywork", exist_ok=True)
path = "mywork/press_data.json"
data = {}
if os.path.exists(path):
    with open(path, encoding="utf-8") as f:
        data = json.load(f)
added = [k for k in NEED if k not in data]
for k in added:
    data[k] = NEED[k]
with open(path, "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
print("입력 준비 완료 — 새로 채운 필드:", added or "없음(앞 차시 결과를 그대로 사용)")
```

**기대 출력**: `입력 준비 완료 — 새로 채운 필드: ...` (앞 차시를 했다면 `없음(앞 차시 결과를 그대로 사용)`)

**이전 차시 파일**: 이 차시의 코드는 `mywork/config.py`(2차시)를 import 하거나 그 파일에 이어서 함수를 추가합니다. 파일이 있는지 `dir mywork\*.py`로 확인하세요.

앞 차시를 건너뛰어 파일이 없다면 아래로 기존 파일을 복사합니다(프로젝트 루트에서 실행).

```powershell
New-Item mywork\__init__.py -ItemType File -Force
Copy-Item modules\config.py mywork\config.py
```

## 4. Claude Code 프롬프트

아래 전체를 복사해 Claude Code에 붙여넣고, 파일 쓰기 승인 요청이 뜨면 승인합니다. 생성 위치는 전부 `mywork/` 안입니다(기존 `modules/`는 건드리지 않습니다).

```text
mywork/stats.py 를 만들어줘. 통계 수치는 전부 파이썬이 계산하고 LLM은 쓰지 않는다. mywork/config.py의 PRIMARY_INDICATOR, PRIMARY_UNIT을 import 해서 쓴다.

1. detect_special_points(momRate, yoyRate, is_record_high, recent_momRates=None) -> list[str]
   아래 순서대로 조건이 맞는 것만 리스트에 추가해 반환:
   - is_record_high가 True → "역대 최대치 경신"
   - abs(momRate) >= 5 → 양수면 "전월 대비 큰 폭 증가", 음수면 "전월 대비 큰 폭 감소"
   - abs(yoyRate) >= 5 → 양수면 "전년동월 대비 큰 폭 증가", 음수면 "전년동월 대비 큰 폭 감소"
   - recent_momRates가 3개 이상이면 마지막 3개가 모두 양수 → "최근 3개월 연속 증가세", 모두 음수 → "최근 3개월 연속 감소세"
2. generate_interpretation(indicator_name, value, unit, point_type) -> str
   특이점 유형별 문장 템플릿 딕셔너리로 문장을 만든다. 지원 유형 8개: "역대 최대치 경신", "전월 대비 큰 폭 증가", "전월 대비 큰 폭 감소", "전년동월 대비 큰 폭 증가", "전년동월 대비 큰 폭 감소", "최대 비중", "최근 3개월 연속 증가세", "최근 3개월 연속 감소세". 없는 유형이면 "" 반환.
   문장은 보도자료체("~하였다", "~이어가고 있다")로 쓴다. 예: "{지표명}이 전월 대비 {값}% 증가하며 큰 폭의 상승세를 보였다." / 감소는 "...감소하며 큰 폭의 하락세를 보였다."
   ★기존과 다른 요구: "역대 최대치 경신"과 "최대 비중" 문장의 값은 천 단위 콤마로 표기하고 조사는 자연스럽게 쓴다(예: "온라인쇼핑 거래액은 201,250억 원으로 역대 최대치를 기록하였다."). 지표명은 받침이 있는 "온라인쇼핑 거래액"으로 쓸 것이므로 조사는 "은/이"로 고정해도 된다.
3. _shift_month(ym, delta_months) -> str : "YYYY-MM" 문자열을 delta_months(음수면 과거)만큼 이동해 같은 형식으로 반환(연 경계 처리).
4. derive_history_indicators(history, current_ym, current_value) -> dict
   - history = [{"연월": "YYYY-MM", "값": 숫자}, ...] (순서 무관, 이번 달 제외)
   - 반환 키 4개: "역대최대여부", "최근3개월증감률", "전월대비증감률", "전년동월대비증감률"
   - history가 비어 있으면 {"역대최대여부": True, "최근3개월증감률": [], "전월대비증감률": None, "전년동월대비증감률": None}
   - ★ 역대최대여부는 "같은 달"(예: 1월)의 과거 값들과만 비교해서, 이번 값이 그 최댓값 이상이면 True(같은 달 과거값이 없으면 True). 월별 규모가 원래 다르므로(명절 등) 다른 달과 섞어 비교하지 않는다.
   - 최근3개월증감률: history와 이번 달을 연월순으로 정렬한 뒤 마지막 3개 구간의 "직전 대비 증감률(%)" 리스트, 소수 첫째 자리 반올림. 직전 값이 0이거나 없으면 그 구간은 건너뛴다.
   - ★ 전월/전년동월 증감률: 비교 기준 연월이 history에 없으면 0이나 임의값으로 채우지 말고 None. 있으면 (이번-기준)/기준*100을 소수 첫째 자리로 반올림.
5. build_interpretation_sentences(특이점, 계산지표, 지표명) -> list[str]
   특이점 목록의 각 항목을 generate_interpretation으로 문장화해 리스트로 반환. 모든 문장의 주어는 지표명.
   - "역대 최대치 경신"에는 계산지표[PRIMARY_INDICATOR]와 PRIMARY_UNIT을 쓴다.
   - ★ 전월 대비는 계산지표["전월대비증감률"], 전년동월 대비는 계산지표["전년동월대비증감률"]을 각각 써서 서로 섞지 않는다.
   - ★ 감소 방향은 abs()로 부호를 뗀 값을 감소 전용 템플릿에 채운다(부호를 두면 "-6% 감소"처럼 이중 부정이 된다).
   - "최근 3개월 연속 증가세/감소세"는 값 없이 문장만 만든다.
6. add_calculated_indicators(data, indicator_name="온라인쇼핑 거래액") -> dict
   - data["계산지표"], data.get("역대최대여부", False), data.get("최근3개월증감률")로 detect_special_points를 호출한다(momRate=전월대비증감률, yoyRate=전년동월대비증감률).
   - ★기존과 다른 요구: 지표명을 제목의 마지막 단어에서 뽑지 말고 indicator_name 인자로 받는다(제목이 "…동향"으로 끝나면 "동향은 …"처럼 어색한 문장이 나오기 때문).
   - data["통계해석결과"] = {"특이점목록": [...], "해석문장": [...]} 를 저장하고 data를 반환.
```

**프롬프트에 꼭 들어간 것과, 빠지면 생기는 문제**

| 프롬프트에 꼭 들어간 것 | 빠지면 생기는 문제 |
| --- | --- |
| 감소 템플릿 + `abs()` | 하락 통계에서 특이점은 잡히는데 해석문장이 조용히 비거나 "-6% 감소"가 됨 |
| 같은 달끼리 비교 | 명절이 낀 달과 그냥 달을 비교해 "역대 최대"를 오판 |
| 비교월이 없으면 `None` | 0으로 채워 잘못된 증감률이 보도자료에 들어감 |
| 전월/전년동월 값 분리 | 전월 증감률로 "전년동월 대비" 문장을 만드는 혼동 |
| `indicator_name` 인자 | "동향은 201250억 원로…"처럼 어색한 문장 |

기존 코드는 `indicator_name` 인자가 없고 제목의 마지막 단어를 지표명으로 쓰므로, 검증 스니펫의 `"동향은"` assert(와 그 아래 콤마 assert)가 **실패하는 것이 정상**입니다(실제로 확인함). `통계해석결과`는 그 assert 앞에서 이미 저장되므로 7차시로 그대로 이어갈 수 있습니다. 실패한 줄은 "기존 코드의 알려진 한계"로 기록만 하세요.
