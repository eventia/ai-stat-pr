## 3. CLAUDE.md 새로 작성 (1분)

`CLAUDE.md`(프로젝트 폴더 바로 아래)는 Claude Code가 **세션을 시작할 때 자동으로 읽는 프로젝트 규칙 파일**입니다. 프롬프트는 "이번 차시에 무엇을 만들지", CLAUDE.md는 "프로젝트 내내 지킬 규칙"을 맡습니다. 이 파일은 세 부분으로 이루어집니다.

| 부분 | 내용 |

| ① 기본 규칙 5줄 | 프로젝트 전체 원칙(계산은 코드로, API 키는 `.env`로, 생성 문장은 교차 검증, 보도자료체, 모델 ID 한 곳 관리). 결과 코드는 `mywork/`에 만들므로 위치도 `mywork/…`로 적습니다 |
| ② 공통 블록 | 10분 실습 공통 규칙(`quick-practice:common` 표시로 감쌈) |
| ③ 차시 블록 | 이번 차시 규칙(`quick-practice:ch02` 표시로 감쌈). **3차시부터는 이 파일 맨 아래에 그 차시 블록만 이어 붙입니다**(①·②는 다시 넣지 않습니다) |

## 10분 실습 공통 규칙 (mywork/)
- 결과 코드는 `mywork/` 패키지 안에만 만든다. 프롬프트의 설명만으로 직접 작성하고, 프로젝트 밖의 다른 코드는 열어보거나 복사하지 않는다.
- `mywork` 안의 모듈끼리는 절대 경로로 import 한다 (예: `from mywork.config import REQUIRED_FIELDS`).
- 프롬프트가 지정한 함수 이름·시그니처를 그대로 쓰고, 요청하지 않은 기능·예외처리·주석·문서 파일은 추가하지 않는다.
- 표준 데이터(`mywork/press_data.json`)의 키 이름은 한글 그대로 쓴다 (`문서정보`, `계산지표`, `핵심내용`, `원문`, `품목별지표`, `월별이력`, `NLP분석결과`, `요약결과`, `통계해석결과`, `시각자료설명`, `헤드라인`, `본문`, `최종본`, `검수결과`).
- 기존 파일에 함수를 추가하라는 요청이면 이미 있는 함수는 고치지 않는다.
- 코드를 만든 뒤에는 `python -c "import mywork.<모듈>"`로 import 오류만 확인하고 끝낸다.

처음 여는 폴더라면 "이 폴더를 신뢰하겠습니까?"라는 질문이 나옵니다. 직접 만든 폴더이므로 신뢰(Yes)를 선택합니다. 아래 전체를 복사해 붙여넣고, 파일 쓰기 승인 요청이 뜨면 승인합니다.

```text
mywork/ 폴더에 다음 3개 파일을 만들어줘. (mywork/__init__.py 는 빈 파일)

[mywork/config.py] — 데이터 딕셔너리(항목 정의)를 상수로 둔다.
- DATA_DICTIONARY: 항목명을 키로 하고 값은 {"영문", "타입", "단위", "등급", "정의"} dict.
  총거래액(total_sales, 정수, "억 원", 필수), 전월대비증감률(mom_rate, 숫자(소수점 1자리), "%", 필수),
  전년동월대비증감률(yoy_rate, 숫자(소수점 1자리), "%", 필수), 품목별지표(category_indicators, 목록, "억 원, %", 선택),
  공표일자(release_date, 날짜(YYYY-MM-DD), "-", 참고), 자료출처(source, 문자열, "-", 참고). 정의는 한 문장으로 쓴다.
- REQUIRED_FIELDS: DATA_DICTIONARY에서 등급이 "필수"인 항목명 목록 (결과: ["총거래액", "전월대비증감률", "전년동월대비증감률"])
- INDICATOR_UNITS: 필수 항목의 {항목명: 단위}
- PRIMARY_INDICATOR = "총거래액", INDICATOR_NAME = "온라인쇼핑 거래액", ISSUER = "국가데이터처"

[mywork/clean.py]
mask_sensitive_info(text: str) -> str
- 주민등록번호(예: 900101-1234567)는 "******-*******"로 치환한다.
- ★ 휴대전화는 앞자리가 010, 011, 016, 017, 018, 019인 여섯 가지 모두(특히 010을 빠뜨리지 말 것)가 대상이다.
  형식은 앞 3자리-가운데 3~4자리-뒤 4자리(예: 010-1234-5678, 011-123-4567)이고, 모두 "010-****-****"로 치환한다.
  앞자리 정규식은 01[016789]처럼 0이 들어가야 한다. 지역번호(예: 02-123-4567)는 바꾸지 않는다.

standardize_date(value: str) -> str
- "2026.3.1", "2026/03/01", "2026-3-1", "2026년 3월 1일"을 모두 "2026-03-01"로 바꾼다. 형식을 알 수 없으면 입력을 그대로 돌려준다.

clean_text(text: str) -> str — 아래 순서대로 적용한다.
- (정제) 연속 공백·줄바꿈을 공백 하나로, 앞뒤 공백 제거, "(주:...)" 형태의 괄호 주석을 앞 공백과 함께 제거한 뒤 공백을 다시 정리
- (표준화) 숫자 바로 뒤의 "억원"→"억 원", "백만원"→"백만 원", "전월대비"→"전월 대비", 문장 끝 "하였음."→"하였다."
- 마지막에 mask_sensitive_info를 적용한다.

clean_and_structure(raw: dict) -> dict
- ★ 입력 raw는 절대 바꾸지 않는다(원본 보존). 결과에 넣는 dict·list 값은 copy.deepcopy로 복사해서 넣는다.
- 반환 구조(키 이름은 한글 그대로):
  {"문서정보": {"제목", "공표일자"(standardize_date 적용), "자료출처"(없으면 "공공데이터포털 Open API"),
               "기준연월"(없으면 ""), "지표명"(없으면 config.INDICATOR_NAME), "보안등급"(없으면 "미확인")},
   "계산지표": raw의 계산지표 그대로, "핵심내용": raw의 핵심내용 그대로, "원문": clean_text(raw의 원문)}
- ★ 계산지표는 다시 계산하거나 바꾸지 않는다. 이 함수는 구조만 표준화한다(계산은 5차시 stats.py가 담당).
- raw에 "품목별지표", "월별이력", "역대최대여부", "최근3개월증감률"이 있으면 계산 없이 그대로(복사해서) 결과에 넣는다.
```

**프롬프트의 ★ 항목과, 빠지면 생기는 문제**

| ★ 항목 | 빠지면 생기는 문제 |
| --- | --- |
| 휴대전화 앞자리 6가지(010 포함), 정규식 `01[016789]` | 실제로 010이 빠진 `01[16789]`가 생성된 적이 있음 → 가장 흔한 010 번호가 마스킹되지 않은 채 LLM으로 전송됨 |
| 입력 raw를 바꾸지 않음(deepcopy) | 원본이 정제본으로 덮여 감사 추적·수치 출처 확인이 불가능해짐(강의 슬라이드 1·18의 원본 보존 원칙) |
| 계산지표를 그대로 통과(계산 금지) | 정제 단계에서 값이 바뀌면 이후 모든 수치 검증의 기준이 흔들림(CLAUDE.md 원칙 1) |
| 표준 구조 키 이름을 한글 그대로 | 3~10차시 모든 코드가 이 키(`문서정보`, `계산지표`…)를 그대로 읽음 |

### 검증이 실패하면 — 수정 요청 1회

`AssertionError`가 나오면 마지막 줄의 메시지가 어느 조건이 틀렸는지 알려 줍니다. 그 메시지를 Claude Code에 그대로 붙여 수정을 요청합니다. 예를 들어 `010-1234-5678 이 마스킹되지 않음`이 나왔다면 이렇게 요청합니다.

```text
check.py 실행 결과 mask_sensitive_info가 "010-1234-5678"을 마스킹하지 못해 assert가 실패했어. mywork/clean.py의 휴대전화 정규식이 010을 빠뜨리고 있어. 010, 011, 016, 017, 018, 019 모두 매칭되도록 01[016789]-\d{3,4}-\d{4} 로 고쳐줘. 다른 부분은 바꾸지 마.
```

고친 뒤 `python check.py`를 다시 실행합니다. 그래도 통과하지 않으면 9절 폴백으로 넘어갑니다.

**무엇을 설명할까**

- 원본 파일(`data/raw_202601.json`)은 그대로이고, 정제본(`press_data.json`)만 표준 형식이 되었습니다 — 강의의 "원본은 보관하고 사본으로 처리" 원칙입니다.

- 011 번호도 `010-****-****`로 가려집니다(앞자리까지 숨김). 지역번호(02)는 휴대전화가 아니라서 그대로입니다.

## 8. (선택, 10분 밖) Open API로 실제 데이터 받기

강의 4소주제(슬라이드 25~29)의 실습입니다. data.go.kr에서 활용신청이 승인되어 인증키가 있을 때만 진행합니다.

1. 프로젝트 폴더에 `.env` 파일을 만들고 `PUBLIC_API_KEY=발급받은_인증키` 한 줄을 적습니다(`notepad .env`). **촬영 화면에 키가 보이지 않게 주의하세요.**
2. 요청 URL과 파라미터 이름은 **API마다 다르므로** 활용신청 페이지의 "활용가이드"를 따릅니다(슬라이드 28의 URL은 설명용 예시입니다).
3. 강의 코드에 오류 처리를 더해 호출합니다(`requests.get(url, params=params, timeout=10)` 후 `response.raise_for_status()`). 받은 응답은 `data/raw_YYYYMM.json`으로 저장하고, 2절처럼 원본은 수정하지 않습니다.

이 부분은 인증키가 필요해 자동 검증에는 포함하지 않았습니다.
