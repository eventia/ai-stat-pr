## 1. 시작 전 체크리스트 (1분)

1. 프로젝트 루트(`main.py`, `modules/`가 있는 폴더)에서 PowerShell을 엽니다.
2. 가상환경을 켭니다.

```powershell
myvenv\Scripts\Activate.ps1
$env:PYTHONUTF8 = "1"
```

3. 이 차시에 필요한 패키지가 설치되어 있는지 확인합니다(`OK`가 나오면 됩니다).

```powershell
python -c "import anthropic; print('OK')"
```

   오류가 나면 `pip install -r requirements.txt` 를 실행합니다.

4. **API 키**: 선택 단계에서만 필요. 필요한 경우 프로젝트 루트의 `.env` 파일에 `ANTHROPIC_API_KEY=발급받은키` 한 줄이 있어야 합니다.
5. **검증 스니펫 실행 방법**: 이 문서의 `검증`·`관찰`·`입력` 코드는 다음 방법으로 실행합니다.
   - 프로젝트 루트에 `check.py`라는 새 파일을 만들고, 코드를 붙여넣어 저장한 뒤 `python check.py` 를 실행합니다. (다른 코드를 실행할 때는 같은 파일을 덮어씁니다. 실습이 끝나면 `check.py`는 지워도 됩니다.)
6. Claude Code는 **프로젝트 루트에서** 시작합니다(터미널에서 `claude`, 또는 데스크톱 앱의 Code 탭에서 이 프로젝트 폴더를 엽니다). CLAUDE.md는 세션 시작 때 읽히므로 3절을 마친 뒤 **새 세션**으로 시작합니다.

## 3. CLAUDE.md 수정·추가

>
> 결과가 나오면 3-1, 3-2는 건너뛰고 3-3부터 하세요. (`CLAUDE.md.bak` 백업이 없다면 지금 `Copy-Item CLAUDE.md CLAUDE.md.bak` 로 만들어 두세요. 이미 3-1을 한 뒤에 만들면 수정본이 백업되니 주의.)

### 3-1. 기존 규칙 3줄 수정

`CLAUDE.md`를 편집기로 열어, 아래 3개 규칙의 **맨 끝에 괄호 문구를 덧붙입니다**(나머지 2개 규칙은 그대로). 실습 코드는 `modules/`가 아니라 `mywork/`에 만들기 때문에, 규칙이 가리키는 위치를 실습용으로도 읽히게 하려는 것입니다.

**1번째 규칙**

```text
수정 전: - 수치 계산(증감률, 비중, 순위 등)은 반드시 `modules/stats.py`의 파이썬 함수가 처리하며, AI 모델에게 계산을 맡기지 않는다.
수정 후: - 수치 계산(증감률, 비중, 순위 등)은 반드시 `modules/stats.py`의 파이썬 함수가 처리하며, AI 모델에게 계산을 맡기지 않는다. (10분 실습에서는 `mywork/stats.py`)
```

**2번째 규칙**

```text
수정 전: - AI가 생성한 문장은 `modules/review.py`의 `verify_numbers`/`cross_check_all_numbers`로 원본 수치와 반드시 교차 검증한다.
수정 후: - AI가 생성한 문장은 `modules/review.py`의 `verify_numbers`/`cross_check_all_numbers`로 원본 수치와 반드시 교차 검증한다. (10분 실습에서는 `mywork/review.py`)
```

**3번째 규칙**

```text
수정 전: - 모델 ID는 `modules/write.py`의 `MODEL_NAME` 상수 한 곳에서만 관리한다.
수정 후: - 모델 ID는 `modules/write.py`의 `MODEL_NAME` 상수 한 곳에서만 관리한다. (10분 실습에서는 `mywork/write.py`)
```

## 4. Claude Code 프롬프트

아래 전체를 복사해 Claude Code에 붙여넣고, 파일 쓰기 승인 요청이 뜨면 승인합니다. 생성 위치는 전부 `mywork/` 안입니다(기존 `modules/`는 건드리지 않습니다).

```text
[mywork/review.py 에 함수 추가]  (4차시에 만든 find_unverified_numbers, verify_numbers는 그대로 두고 이어서 추가)
필요 import: json, re, mywork.write의 client, MODEL_NAME, parse_json_response

- assemble_full_text(data) -> str : data["헤드라인"]["리드문"] + "\n\n" + 본문의 모든 단락 "내용"을 "\n\n"으로 이어붙인 문자열.
- cross_check_all_numbers(final_text, data) -> dict : {"통과": bool, "불일치수치": find_unverified_numbers(final_text, data)}. ★ 4차시의 함수를 그대로 재사용한다(요약 검증과 최종본 검증이 서로 다른 기준을 쓰면 안 된다).
- unify_style(draft_text) -> str : LLM(max_tokens=1000)으로 문체를 통일한다. 프롬프트: 모든 문장을 객관적 서술체("~하였다")로 통일, 주관적 수식어 제거, 사실과 수치는 절대 변경 금지, ★숫자는 원문 표기(예: 201,250억 원)를 그대로 유지하고 조/억 단위로 다시 쓰지 말 것, ★"수정한 보도자료 본문만 출력하고 수정 내용에 대한 설명이나 목록은 덧붙이지 말 것". 응답은 .strip() 해서 반환.
- check_formatting_errors(text) -> list[str] : 정규식 기반 1차 필터(완벽하지 않으며 최종 확인은 사람이 한다).
  (1) "억원"이 들어 있으면 "단위 표기 오류: '억원'은 '억 원'으로 띄어써야 함"
  (2) 콤마 없는 5자리 이상 숫자(정규식 (?<!\d)\d{5,}(?!\d))가 있으면 "천 단위 구분 콤마 누락 의심: 콤마 없는 5자리 이상 숫자 발견"
  (3) "비중" 뒤 10자 이내에 증가|감소|확대|축소가 있는데 문서 전체에 "%p"가 없으면 "비중(구성비) 변화 표현에는 %p 표기가 필요한지 확인 필요"
  해당하는 메시지 문자열만 리스트로 반환(없으면 []).
- review_press_release(final_text, data) -> list[dict] : AI 제3자 감수.
  * ★ 근거자료 = data 중 "계산지표", "통계해석결과", "품목별지표", "역대최대여부", "최근3개월증감률" 키(있는 것만)를 골라 만든 dict. 이것을 프롬프트에 json.dumps(ensure_ascii=False)로 함께 준다. (계산지표만 주면 감수자가 "역대 최대", "3개월 연속 증가" 같은 표현을 근거 없는 과장으로 오판한다)
  * 프롬프트: "통계 보도자료 전문 감수자" 역할, 수치 오류·과장된 표현·문체 불일치·논리적 비약을 지적, ★"지적사항은 최대 5건까지, 항목당 한 문장"으로 제한, JSON 배열로만 답하라: [{"유형": "...", "위치": "...", "지적사항": "..."}]
  * ★ max_tokens=1500 (짧으면 응답이 중간에 잘려 JSON 파싱이 깨진다)
  * ★ parse_json_response가 ValueError(json.JSONDecodeError 포함)를 던지면 예외를 밖으로 던지지 말고 [{"유형": "감수 응답 파싱 실패", "위치": "-", "지적사항": "AI 감수 응답이 잘리거나 JSON 형식이 아니어서 자동으로 해석하지 못했습니다."}]를 반환한다. (AI 감수는 안전장치 3단계 중 하나일 뿐이므로 이 단계가 실패해도 전체 파이프라인이 멈추면 안 된다)
```

**프롬프트에 꼭 들어간 것과, 빠지면 생기는 문제**

| 프롬프트에 꼭 들어간 것 | 빠지면 생기는 문제 |
| --- | --- |
| 4차시 검증 함수 재사용 | 요약과 최종본의 검증 기준이 갈라짐 |
| 숫자 표기 유지·"본문만 출력" | 문체 통일 중 조/억 환산이나 설명 문장이 섞여 수치 검증 실패 |
| 근거자료 5개 키 전달 | AI 감수가 정상 표현을 과장으로 오판 |
| 최대 5건 + `max_tokens` 1500 + 파싱 실패 폴백 | 감수 응답이 잘리면 파이프라인 전체가 크래시 |

## 7. 함정 관찰 (2분) — "82.0%"는 어디서 왔을까

이 차시에서 프롬프트의 ★ 항목이 왜 필요한지 눈으로 확인합니다. `check.py`로 저장해 실행합니다.

```python
# 관찰 Ch09
import sys, json
sys.path.insert(0, ".")
from mywork.review import find_unverified_numbers

with open("mywork/press_data.json", encoding="utf-8") as f:
    data = json.load(f)
print("세 품목 비중의 합:", round(32.3 + 25.8 + 23.9, 1))
print("원본 품목별 비중:", [row["비중"] for row in data["품목별지표"]])
print("검증이 잡은 수치:", find_unverified_numbers("상위 세 품목이 전체의 82.0%를 차지하였다.", data))
```

**예시 출력**(생성된 코드에 따라 표현은 조금 다를 수 있습니다)

```text
세 품목 비중의 합: 82.0
원본 품목별 비중: [32.3, 25.8, 23.9, 13.0, 5.0]
검증이 잡은 수치: ['82.0']
```

**무엇을 볼 것인가**

- 82.0%는 원본 어디에도 없고, 세 품목 비중을 **AI(본문)가 스스로 더한 값**입니다. 수치 교차 검증이 정확히 이것을 잡아냈습니다.
- 이것이 "계산은 프로그램이, 문장은 AI가"라는 원칙이 필요한 이유입니다. 해결은 (1) 본문 프롬프트에 새로 계산하지 말라고 지시하거나(8차시), (2) 상위 N개 누적 비중을 `stats`가 미리 계산해 `계산지표`에 넣어주는 것입니다. 이번 실습에서는 고치지 않고 **검증이 잡아낸다는 사실**만 확인합니다.

## 8. (선택) 실제 API 호출

(선택 · 실제 비용 발생, API 2회) 문체 통일과 AI 감수를 실제로 실행:

```python
import sys, json
sys.path.insert(0, ".")
from mywork.review import (assemble_full_text, unify_style, check_formatting_errors,
                           cross_check_all_numbers, review_press_release)

with open("mywork/press_data.json", encoding="utf-8") as f:
    data = json.load(f)
data["최종본"] = unify_style(assemble_full_text(data))
data["검수결과"] = {
    "표기오류검사": check_formatting_errors(data["최종본"]),
    "수치교차검증": cross_check_all_numbers(data["최종본"], data),
    "AI감수지적사항": review_press_release(data["최종본"], data),
}
print(data["최종본"])
print(json.dumps(data["검수결과"], ensure_ascii=False, indent=2))
with open("mywork/press_data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

생성이 끝나지 않거나 검증이 끝내 통과하지 않으면, 기존 파일을 복사해 다음으로 넘어갑니다(PowerShell, 프로젝트 루트).

```powershell
New-Item mywork\__init__.py -ItemType File -Force
Copy-Item modules\config.py mywork\config.py

Get-ChildItem mywork\*.py | ForEach-Object {
    (Get-Content $_.FullName -Raw -Encoding UTF8) -replace 'from modules\.io','from mywork.data_io' -replace 'from modules\.(?!export)','from mywork.' | Set-Content $_.FullName -Encoding UTF8
}
```

복사한 기존 파일도 그대로 검증을 통과해야 합니다.

위 명령의 마지막 부분이 복사한 파일의 import 경로를 `modules.`에서 `mywork.`로 바꿉니다(그래야 복사한 파일이 여러분이 만든 `mywork/write.py` 등을 함께 씁니다. `main.py`의 `modules.export`만 그대로 남습니다). 모든 명령은 **프로젝트 루트에서 실행**하고, 복사 후에는 6절 검증만 다시 실행합니다.

## 10. 문제 해결

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `cross_check_all_numbers`가 `통과: True`로 나옴 | 시드의 `본문`(82.0% 포함)이 아닌 다른 본문이 입력에 들어 있음 | 입력 준비 스니펫의 `본문`을 확인하거나, 82.0이 들어간 문장을 본문에 넣고 재실행 |
| `ModuleNotFoundError: No module named 'mywork'` | 프로젝트 루트가 아닌 곳에서 실행했거나 `mywork/__init__.py`가 없음 | 프로젝트 루트로 이동(`cd`) 후 다시 실행. `New-Item mywork\__init__.py -ItemType File -Force` |
| 한글이 `???`·깨진 글자로 출력 | PowerShell 기본 코드페이지(cp949) | `$env:PYTHONUTF8 = "1"` 후 다시 실행 |
| `ModuleNotFoundError: No module named 'pandas'` 등 패키지 없음 | 가상환경 미활성화 또는 미설치 | `myvenv\Scripts\Activate.ps1` 후 `pip install -r requirements.txt` |
| Claude Code가 `modules/`를 열어 보거나 복사해서 만듦 | CLAUDE.md 규칙이 적용되지 않음 | 3절을 다시 확인하고 **새 세션**으로 시작. 이미 만들어졌다면 그 파일을 지우고 프롬프트를 다시 붙여넣기 |
| `AssertionError`가 나옴 | 생성 코드가 프롬프트의 ★ 항목 중 일부를 빠뜨림 | 오류 메시지와 `check.py` 결과를 Claude Code에 **그대로 붙여** 수정 요청(1회). 그래도 안 되면 폴백 |
| 생성이 4분 넘게 끝나지 않음 | 생성 지연 또는 프롬프트 오해 | 중단하고 폴백(9절)으로 진행. 검증 스니펫은 그대로 실행 |
