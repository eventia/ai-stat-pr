# 10분 실습 검토와 진행안

작성일: 2026-09-19 · 성격: **검토 결과 + 진행안**(기존 문서·코드는 수정하지 않음)
짝 문서: [02-클로드코드프롬프트.md](02-클로드코드프롬프트.md) — 차시별 Claude Code 프롬프트와 검증 스니펫

## 0. 전제와 범위

- **"10분"의 해석(가정)**: 각 차시(2~10차시)의 실습 시간이 10분이다(강의 25분 내외 + 실습 10분). 9개 차시이므로 10분 트랙 전체는 약 90분입니다. *다르게 의도하셨다면 알려주세요(7절 질문 1).*
- **두 가지 진행 방향**
  - **트랙 A — 표준 실습**: 기존 `labs/Ch02~Ch10-실습.md`를 그대로 진행(이미 만들어진 코드를 실행하며 결과를 읽음)
  - **트랙 B — 10분 실습**: 차시당 핵심 하나만, **Claude Code가 코드를 직접 생성**하고 짧은 스니펫으로 검증
- 이 문서와 `02-…` 문서는 모두 새 문서입니다. 기존 `labs/`, `modules/`, `TASKS.md` 등은 수정하지 않았습니다.

## 1. 현재 실습(트랙 A)이 10분을 넘는 이유

### 1-1. 분량 (측정: 문서 구조를 센 값)

| 차시 | 단계 수 | 코드 블록 | 문서 줄 수 | 실제 LLM 호출(측정) | 추정 소요 |
| --- | --- | --- | --- | --- | --- |
| 2 | 13 | 16 | 370 | 0 | 약 40분 (공공 API 발급·실연동 구간은 별도 +10~20분) |
| 3 | 8 | 14 | 187 | 0 | 약 32분 |
| 4 | 7 | 12 | 183 | 1 | 약 28분 |
| 5 | 8 | 14 | 238 | 0 | 약 32분 |
| 6 | 8 | 12 | 214 | 0 (선택 1) | 약 28분 |
| 7 | 8 | 12 | 194 | 1 | 약 28분 |
| 8 | 5 | 7 | 147 | 최대 6 (1단계 3 + 3단계 3) | 약 18분 |
| 9 | 6 | 10 | 167 | 2 | 약 24분 |
| 10 | 5 | 8 | 153 | 4~6 (아래 1-3) | 약 20분 |
| **합계** | | | | | **약 250분(4시간 10분)** |

- **"추정 소요"는 실측이 아닙니다.** 계산식: 코드 블록 1개당 2분(복사·실행·결과 읽기) + 단계당 해설 읽기 0.5분 + API 응답 대기. 실제 학습자로 재본 시간이 아니므로 참고용으로만 보세요.
- 차시당 평균 약 28분 → 10분으로 줄이려면 분량을 약 1/3로 줄여야 합니다.

### 1-2. 오래 걸리는 구조적 원인

1. **차시마다 반복되는 보일러플레이트**: 데이터 불러오기·저장·경로 설정 블록이 매 차시 2~3개씩 있음
2. **같은 기능을 두 번 실행**: 8차시는 `expand_to_paragraph`를 손으로 반복(1단계)한 뒤 `generate_body_paragraphs`(3단계)로 똑같이 다시 실행 → API 호출 중복
3. **개념 설명·"왜 이런 결과인가" 해설이 실행 단계 사이에 끼어 있음**(00-실습실행순서.md는 이를 주석 처리해 줄였지만 실행 자체가 줄지는 않음)
4. **단계별 단위 테스트를 차시마다 별도 단계로 실행**
5. **선택/응용 구간이 본 흐름과 섞임**: 공공 API 발급·실연동(2차시), LLM 다듬기(6차시), 반려동물 예시(10차시)
6. **코드를 읽고 붙여 넣는 데 시간이 듦**: 함수 하나에 수십 줄

### 1-3. 검토 중 확인한 사실 — 기존 문서의 부정확한 서술 (수정하지 않고 기록만)

`main.py`의 LLM 호출 횟수를 가짜 클라이언트로 직접 세어 보았습니다(임시 폴더에서 실행, 저장소 파일은 변경 없음).

| 입력 파일 | LLM 호출 | 본문 단락 | 시각자료설명 |
| --- | --- | --- | --- |
| `data/raw/온라인쇼핑동향_2026_01.xlsx` (기본) | **4회** | **0** | 0 |
| `data/raw/온라인쇼핑동향_2026_01_상세.xlsx` | **6회** | **2** | 2 |

- 기본 xlsx에는 `품목별지표` 열이 없어 그래프·본문이 만들어지지 않습니다(열: 연월, 총거래액, 전월대비증감률, 전년동월대비증감률, 원문).
- 따라서 `labs/Ch10-실습.md`와 `labs/00-실습실행순서.md`의 **"API 5회 호출(본문 3단락 포함)"** 서술은 실제와 달랐습니다(기본 xlsx 4회, 상세 xlsx 6회). **→ 2026-09-19 PDF·HWPX 출력 추가 작업 때 두 문서의 호출 횟수는 정정했습니다.** 또 `Ch10-실습.md` 4단계는 손으로 쌓은 결과(본문 있음)와 `main.py` 결과를 비교하라고 하는데, 기본 xlsx로 실행한 `main.py`의 최종본에는 본문이 없어 같은 조건의 비교가 아닙니다.
- 10분 트랙의 10차시는 이 사실을 반영해 **`_상세.xlsx`를 기본 입력**으로 씁니다.

## 2. 10분 안에 담을 핵심을 고르는 원칙

1. **차시당 산출물은 "함수 묶음 하나 + 표준 데이터의 필드 하나"** 로 한정
2. **학습목표의 핵심 1개 + 프로젝트에서 실제로 겪은 함정 1개**를 남김 (함정은 프롬프트의 ★ 항목이자 검증 스니펫의 assert가 됨)
3. **검증은 오프라인 우선**: 가짜 응답·스니펫으로 무료·즉시 검증, 실제 API 호출은 차시당 0~1회(10차시만 예외)
4. **개념 설명·선택·응용은 제외**(개념은 강의에서 다룸)
5. **생성이 실패해도 진행이 끊기지 않게** 폴백(기존 `modules/` 복사)과 시드 데이터를 준비
6. **각 차시가 독립 진행 가능**하도록 시드 스니펫 제공(앞 차시를 못 했어도 시작 가능)

## 4. 차시 공통 10분 타임라인

| 시각 | 할 일 | 비고 |
| --- | --- | --- |
| 0:00–1:00 | 입력 확인 | `mywork/press_data.json` 있는지, 없으면 시드 스니펫(02 문서) |
| 1:00–3:00(최대 4:00) | 프롬프트 붙여넣기 → Claude Code 생성 → 승인 | 생성 파일이 `mywork/`에 저장되는지 확인 |
| 3:00–6:00 | 검증 스니펫 실행 → 기대 결과와 비교 | 실패하면 오류 메시지를 Claude Code에 그대로 붙여 수정 요청(1회) |
| 6:00–8:00 | **함정 1개 관찰** | 예: 3차시 "거래액이 왜 빠졌나", 9차시 "82.0%가 왜 잡혔나" |
| 8:00–9:30 | 저장 확인, 다음 차시 입력 확인 | 검증 스니펫이 `mywork/press_data.json`을 자동 갱신 |
| 9:30–10:00 | 결과 기록 | 생성 성공/폴백 사용 여부, 의심 가는 점 메모 |

- **폴백 판단 시점은 4:00**입니다. 그때까지 생성·검증이 안 끝나면 기존 파일을 복사하고(02 문서의 차시별 `copy` 명령) 검증만 진행합니다.
- 폴백 후 일부 assert가 실패하는 것은 정상인 경우가 있습니다(5차시 "동향은", 8차시 "계산" 문구) — 02 문서에 각각 적어 두었고, **실제로 그렇게 되는 것을 확인했습니다.**

## 7. 이번 검토에서 확인·발견한 것 (결정이 필요한 항목 포함)

### 확인한 것 (검증 방법)
- 02 문서의 **검증 스니펫 9개(seed, 2~9차시)를 문서에서 자동 추출해 실행**했습니다. 기존 `modules/`를 임시 폴더에 `mywork/` 패키지로 복사하고 프롬프트가 요구한 개선(★기존과 다른 요구)만 패치한 "이상적으로 생성된 코드"에서 **전부 통과**, 10차시 확인 스니펫도 가짜 LLM으로 `main`을 돌린 뒤 통과했습니다.
- **패치 없는 기존 코드를 그대로 복사한 폴백**에서는 5차시("동향은"), 8차시("계산")의 지정된 assert만 실패하고 나머지는 통과합니다(문서에 그대로 안내).
- **한계**: 실제 Claude Code가 생성한 코드로 검증한 것은 **아닙니다.** 생성 결과는 실행마다 달라질 수 있으므로, 실제 수업 전에 강사가 한 번 시험 생성해 보는 것을 권합니다. 생성에 걸리는 시간도 측정하지 못했습니다(4절의 시간 배분은 설계값).
- 실제 Claude API는 호출하지 않았습니다(비용 방지).

### 프롬프트가 기존 코드와 일부러 다르게 요구한 점 (채택 여부 결정 필요)
| 항목 | 기존 코드 | 프롬프트 요구 | 이유 |
| --- | --- | --- | --- |
| 지표명 (5차시) | 제목의 마지막 단어(`split()[-1]`) → "동향은 …" | `indicator_name` 인자, 기본 "온라인쇼핑 거래액" | 이미 기록된 어색한 문장 문제 |
| 해석문 숫자 (5차시) | "201250억 원로"(콤마 없음, 조사 오류) | "201,250억 원으로" | 콤마 없는 5자리 이상 숫자는 9차시 `check_formatting_errors`가 잡는 형태 — 현재는 해석문이 최종본에 직접 안 들어가 드러나지 않을 뿐 |
| 본문 확장 프롬프트 (8차시) | 파생 수치 금지 문구 없음 | "새로 계산(합계·평균·비율)하지 말 것" 추가 | AI가 82.0%를 만들어 9차시 검증에 걸린 재현 사례 |
| 입력 모듈 이름 (7차시) | `modules/io.py` | `mywork/data_io.py` | 패키지 밖에서 실행할 때 표준 라이브러리 `io` 충돌 방지 |
| 10차시 입력 | 기본 xlsx(본문 0단락) | `_상세.xlsx`(본문 2단락) | 1-3 발견 사항 |
