# 보도자료 자동생성 10분 단축 실습(labs/quick) 진행 가이드

> **작성 위치**: `labs/quick/antigravity/실습진행가이드.md`  
> **성격**: 사용자의 안전하고 체계적인 실습 수행을 돕기 위한 **조언 및 진행 가이드 문서**  
> **주의사항**: 기존 프로젝트 파일(`labs/`, `modules/`, `data/` 등)은 일절 수정하지 않으며, 모든 산출물은 `mywork/` 패키지에 격리 작성합니다.

---

## 1. 실습 개요 및 학습 목표

### 1-1. 실습 배경 및 트랙 정의
본 실습은 통계 데이터를 입력받아 공공 보도자료(텍스트, 그래프 이미지, PDF, HWPX)를 자동 생성하는 파이프라인을 구축하는 실습입니다.

- **트랙 A (표준 실습, 기존 `labs/`)**: 이미 작성된 완성형 모듈(`modules/`)을 단계별로 실행하며 원리를 학습 (차시당 20~40분 소요)
- **트랙 B (10분 단축 실습, `labs/quick/`)**: 각 차시별 핵심 기능 1개를 선정하고, **Claude Code에게 프롬프트를 주어 `mywork/` 폴더에 직접 코드를 생성**하게 한 뒤, 초단기 검증 스니펫으로 동작 및 핵심 함정을 확인 (차시당 10분 내외 소요)

### 1-2. 3대 절대 원칙
1. **수치 계산은 코드가 수행 (LLM 계산 금지)**: 증감률, 순위, 비중, 합계 등 통계 수치는 반드시 파이썬 함수가 연산하며, LLM은 문장화와 서술에만 집중합니다.
2. **엄격한 수치 검증 및 환각 방지**: LLM이 작성한 모든 문장의 숫자는 원본 데이터와 교차 검증(`verify_numbers`)합니다.
3. **환경 격리 및 기존 자산 보존**: 기존 완성 코드(`modules/`)는 절대 덮어쓰지 않고, 생성 코드는 오직 `mywork/` 안에만 만듭니다.

## 4. 10분 실습 표준 타임라인 & 운영 가이드

각 차시를 10분 내에 효율적으로 끝내기 위해 아래 시간 배분을 권장합니다.

```
[0:00 ~ 1:00] 입력 데이터 및 환경 확인 (mywork/press_data.json 유무 확인)
     │
[1:00 ~ 3:00] Claude Code에 차시별 프롬프트 전달 및 코드 생성 승인
     │
[3:00 ~ 4:00] 검증 스니펫 1차 실행
     │
     ├── 성공 시 ──> [4:00 ~ 7:00] 차시별 핵심 함정 관찰 및 데이터 확인
     │                    │
     └── 실패 시 ──> [4:00 시점 즉시 폴백(Fallback)] 기존 모듈 복사 후 진행
                          │
[7:00 ~ 9:00] (선택 사항) 실제 LLM API 호출 테스트
     │
[9:00 ~ 10:00] 다음 차시를 위한 저장 확인 및 회고
```

### 4-1. 4분 폴백(Fallback) 기준
- 프롬프트 생성 코드가 에러를 내거나 검증을 통과하지 못해 디버깅 시간이 **4분을 초과**할 경우, 학습 흐름 유지를 위해 즉시 기존 완성 모듈을 복사(`Copy-Item`)하여 다음 단계로 넘어갑니다.
- **폴백 공통 후처리**: 복사된 파일들이 서로를 참조할 때 `modules.` 대신 `mywork.`를 참조하도록 PowerShell 명령으로 일괄 치환합니다.

```powershell
# 폴백 후처리 명령어 (필요 시 프로젝트 루트에서 실행)
if (-not (Test-Path mywork\config.py)) { Copy-Item modules\config.py mywork\config.py }
Get-ChildItem mywork\*.py | ForEach-Object {
    (Get-Content $_.FullName -Raw -Encoding UTF8) -replace 'from modules\.io','from mywork.data_io' -replace 'from modules\.(?!export)','from mywork.' | Set-Content $_.FullName -Encoding UTF8
}
```

### 4-2. 시드 데이터(Seed Data) 활용
- 특정 차시부터 단독으로 실습을 시작하거나 이전 차시 데이터가 유실되었을 때는 `02-클로드코드프롬프트.md`의 **시드 스니펫**을 실행하여 표준 `mywork/press_data.json`을 즉시 생성할 수 있습니다.

## 5. Antigravity의 조언자 역할 및 협업 방식

사용자께서 각 차시 실습을 진행하실 때, 저는 다음과 같이 지원해 드리겠습니다:

1. **기존 파일 무수정 원칙 준수**: 원본 가이드나 기존 코드를 절대 임의로 고치지 않고 순수한 멘토/조언자 역할을 수행합니다.
2. **차시 시작 전 핵심 함정 브리핑**: 프롬프트 입력 전, 해당 차시에서 놓치기 쉬운 핵심 요소(★ 표시 항목)를 요약 안내합니다.
3. **검증 결과 분석 및 트러블슈팅**: 스니펫 실행 결과 오류가 발생하거나 수치 불일치가 나타났을 때, 코드의 어떤 부분이 어긋났는지 정확한 원인을 분석해 드립니다.
4. **폴백 전환 시점 가이드**: 4분이 초과되어 지체될 때 적절한 폴백 명령어를 안내하여 실습 흐름이 끊기지 않도록 돕습니다.
