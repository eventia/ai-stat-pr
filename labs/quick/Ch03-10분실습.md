## 4. Claude Code 프롬프트

CLAUDE.md를 바꿨으므로 **Claude Code를 새로 시작**합니다(`claude`). 아래 전체를 붙여넣고 파일 쓰기를 승인합니다.

```text
mywork/nlp.py 를 만들어줘. 생성형 AI는 쓰지 않고 형태소 분석·TF-IDF·TextRank만 쓴다.
(kiwipiepy, scikit-learn, networkx 사용)

- 모듈 전역에서 Kiwi()를 한 번만 만들고, "온라인쇼핑", "모바일쇼핑", "거래액", "역대급"을
  add_user_word(단어, "NNP", 0.0)로 사용자 사전에 등록한다.
- STOPWORDS = {"등", "및", "수", "것"}

extract_nouns(text: str) -> list
- Kiwi tokenize 결과 중 품사 태그가 "NN"으로 시작하는 토큰의 form만 순서대로 돌려준다.

split_sentences(text: str) -> list
- 마침표·느낌표·물음표 뒤의 공백을 기준으로 나눈다(re.split(r"(?<=[.!?])\s+", ...)). 앞뒤 공백 제거, 빈 문장 제외.

clean_keywords(keyword_scores, top_n: int = 5) -> list
- 불용어와 한 글자 단어를 빼고, 점수 내림차순으로 상위 top_n개의 (단어, 점수)를 돌려준다.

extract_keywords_tfidf(text: str, top_n: int = 5) -> list
- ★ 문서가 1건이므로 문장 하나하나를 문서로 취급한다: 문장별 명사를 공백으로 이어 붙인 문자열 목록(빈 것 제외)에 TfidfVectorizer를 적용한다.
- 단어마다 여러 문장 중 최고 점수를 대표 점수로 쓴다. 단어는 str, 점수는 파이썬 float(소수점 4자리 반올림)로 만든다.
- 마지막에 clean_keywords(..., top_n)로 정리해 돌려준다.

extract_main_sentences(sentences: list, ratio: float = 0.5) -> list   (TextRank)
- 문장이 1개 이하면 그대로 돌려준다.
- 문장별 명사 문자열(명사가 없으면 원 문장)을 TF-IDF로 벡터화하고 cosine_similarity로 유사도 행렬을 만든다.
- ★ 대각선(자기 자신과의 유사도)을 0으로 만든 뒤 networkx.from_numpy_array → pagerank로 점수를 구한다.
- 점수 상위 max(1, round(문장수 * ratio))개를 고르되, ★ 원문 순서대로 돌려준다(문장은 고치지 않고 그대로).

filter_sentences_by_keywords(sentences: list, keywords: list) -> list
- 키워드를 하나라도 포함한 문장만 원래 순서대로 돌려준다.

analyze_document(raw_text: str, standard_data: dict) -> dict
- 키워드(단어만) = extract_keywords_tfidf(raw_text)
- 주요문장 = extract_main_sentences(split_sentences(raw_text))를 filter_sentences_by_keywords로 다시 거른 것
- standard_data["NLP분석결과"] = {"핵심키워드": [...], "주요문장": [...]} 로 넣고 standard_data를 돌려준다.
```

**프롬프트의 ★ 항목과, 빠지면 생기는 문제**

| ★ 항목 | 빠지면 생기는 문제 |
| --- | --- |
| 문장 단위 코퍼스로 TF-IDF | 문서 1건이면 IDF가 모두 같아져 **단순 빈도**와 다를 바 없어짐(7절 ②에서 직접 확인) |
| 대각선(자기 유사도) 0 | 각 문장이 자기 자신과 1.0으로 연결되어 PageRank 점수가 왜곡됨 |
| 원문 순서로 반환 | 추출 결과를 원문과 대조하기 어려워지고, 요약 문장 순서가 뒤섞임 |
| 파이썬 float로 반환 | numpy 숫자(`np.float64`)가 섞여 출력이 지저분해지고 이후 JSON 저장·비교가 번거로움 |

## 7. 관찰 — 사용자 사전과 문서 1건 TF-IDF의 한계

```python
# 관찰 Ch03
import sys, json
sys.path.insert(0, ".")
from kiwipiepy import Kiwi
from sklearn.feature_extraction.text import TfidfVectorizer
from mywork.nlp import extract_nouns, split_sentences, extract_keywords_tfidf

with open("mywork/press_data.json", encoding="utf-8") as f:
    text = json.load(f)["원문"]

# ① 사용자 사전이 없으면 복합명사가 쪼개진다
기본 = Kiwi()
print("① 사전 없음:", [t.form for t in 기본.tokenize("온라인쇼핑 거래액") if t.tag.startswith("NN")])
print("① 사전 등록:", extract_nouns("온라인쇼핑 거래액"))

# ② 원문 전체를 문서 1건으로 넣으면 → 점수가 단순 빈도와 같아진다
v = TfidfVectorizer()
m = v.fit_transform([" ".join(extract_nouns(text))])
점수 = sorted(zip(v.get_feature_names_out(), m.toarray()[0]), key=lambda x: -x[1])[:4]
print("② 문서 1건:", [(str(w), round(float(s), 3)) for w, s in 점수])

# ③ 문장 단위로 나누면 → 특정 문장에만 나오는 단어가 높아지고, 여러 문장에 나오는 '거래액'은 낮아진다
for i, s in enumerate(split_sentences(text), 1):
    print(f"③ 문장{i}:", extract_nouns(s))
print("③ 문장 단위 상위 8:", extract_keywords_tfidf(text, top_n=8))
```

**예시 출력**

```text
① 사전 없음: ['온라인', '쇼핑', '거래액']
① 사전 등록: ['온라인쇼핑', '거래액']
② 문서 1건: [('거래액', 0.392), ('대비', 0.392), ('증가', 0.392), ('기록', 0.196)]
③ 문장1: ['년', '월', '온라인쇼핑', '거래액', '원', '전월', '대비', '증가']
③ 문장2: ['전년', '동월', '대비', '증가', '수치']
③ 문장3: ['역대', '월', '기준', '최대', '기록', '것']
③ 문장4: ['모바일쇼핑', '거래액', '비중', '전체', '차지', '증가세']
③ 문장 단위 상위 8: [('온라인쇼핑', 0.5087), ('전월', 0.5087), ('기록', 0.5), ('기준', 0.5), ('역대', 0.5), ('최대', 0.5), ('동월', 0.4855), ('수치', 0.4855)]
```

**무엇을 설명할까**

- ① 사용자 사전이 없으면 "온라인쇼핑"이 "온라인"+"쇼핑"으로 쪼개져 키워드로 잡히지 않습니다(슬라이드 8의 실무 팁).
- ② 문서가 1건이면 IDF를 비교할 다른 문서가 없어 점수가 **단순 빈도**와 같아집니다. 두 번 나온 거래액·대비·증가가 0.392, 한 번 나온 단어는 모두 0.196입니다 — 흔한 단어를 걸러 내지 못합니다(슬라이드 9 노트). (TfidfVectorizer는 기본값으로 한 글자 단어를 빼기 때문에 '월'·'년'은 보이지 않습니다.)
- ③ "거래액"은 문장1·문장4 두 곳에 나와 문장 단위 IDF가 낮아져 상위에서 빠집니다. 불용어("것")와 한 글자("월", "년")는 `clean_keywords`가 걸러 냅니다(슬라이드 10).

## 10. 문제 해결

| 증상 | 원인 | 조치 |
