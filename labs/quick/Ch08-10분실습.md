## 4. Claude Code 프롬프트

Claude Code를 **새로 시작**(`claude`)하고 아래를 붙여넣습니다.

```text
mywork/write.py 에 함수 3개와 상수 1개를 추가해줘(기존 함수는 고치지 말 것).

CONNECTIVES = ["", "한편, ", "아울러, "]

expand_to_paragraph(subtopic: str, source_facts: str) -> str
- 프롬프트: "아래 그래프 설명 소재를 바탕으로 통계 보도자료의 본문 한 단락(3~4문장)을 작성해 주세요."
  조건: 두괄식 구조(핵심 수치 먼저), 제공된 사실 외의 내용 추가 금지,
  ★ "소재에 없는 합계·차이·비율 등을 새로 계산해서 쓰지 말고, 숫자는 소재의 표기(콤마·단위 포함) 그대로 쓸 것",
  "연결어('한편,' 등)로 시작하지 말고 단락 본문만 출력할 것". 그 아래에 "소주제: …", "설명 소재: …"를 넣는다.
- call_claude(prompt, max_tokens=1500) 결과를 돌려준다.

generate_body_paragraphs(data: dict) -> list
- data["시각자료설명"]의 항목마다 expand_to_paragraph(항목["소주제"], 항목["설명문"])를 부르고 strip() 한다.
- ★ 결과가 빈 문자열이면 건너뛴다.
- ★ 연결어는 지금까지 실제로 추가된 단락 수를 기준으로 CONNECTIVES에서 고른다(첫 단락 "", 둘째 "한편, ", 셋째부터 "아울러, ").
  연결어를 그대로 앞에 붙인다(lower() 등 대소문자 처리는 하지 않는다).
- [{"소주제": ..., "내용": 연결어 + 단락}, ...] 목록을 돌려준다.

assemble_body(paragraphs: list) -> str
- 항목이 dict면 "내용"을, 문자열이면 그대로 써서 빈 줄("\n\n")로 이어 붙인다.
```

**프롬프트의 ★ 항목과, 빠지면 생기는 문제**

| ★ 항목 | 빠지면 생기는 문제 |
| --- | --- |
| 새 계산 금지 | "상위 세 품목이 전체의 82.0%" 같은 **파생 수치**를 AI가 스스로 계산해 넣음 — 계산은 프로그램이 한다는 원칙 위반(슬라이드 19의 검토 의견, 7절에서 확인) |
| 빈 응답 건너뛰기 | 빈 단락이 들어가거나 `내용[0]`에서 `IndexError` |
| 실제로 추가된 단락 수 기준 연결어 | 중간 단락이 빠지면 둘째 단락이 "아울러,"로 시작하는 어색한 흐름 |

## 7. 관찰 — 맞는 계산이라도 원본에 없는 숫자는 걸러진다

```python
# 관찰 Ch08
import sys, json
sys.path.insert(0, ".")
from mywork.review import find_unverified_numbers

with open("mywork/press_data.json", encoding="utf-8") as f:
    data = json.load(f)
비중 = [r["비중"] for r in data["품목별지표"][:3]]
문장 = "품목별 비중을 살펴보면 의류가 32.3%로 가장 컸으며, 상위 세 품목이 전체의 82.0%를 차지하였다."
print("상위 3개 비중:", 비중, "→ 합계", round(sum(비중), 1))
print("근거 없는 숫자:", find_unverified_numbers(문장, data))
```

**예시 출력**

```text
상위 3개 비중: [32.3, 25.8, 23.9] → 합계 82.0
근거 없는 숫자: ['82.0']
```

**무엇을 설명할까**: 82.0%는 계산 자체는 맞지만 원본 데이터에 없는 **파생 수치**입니다. AI가 스스로 계산한 숫자는 검증할 근거가 없으므로 걸러 내고, 필요하면 5차시처럼 **프로그램이 계산해 데이터에 넣은 뒤** 문장에 쓰게 합니다. 그래서 프롬프트에 "새로 계산하지 말 것"을 넣었습니다.

## 8. 실제 API 호출 (권장, 3회)

```python
# 선택 Ch08 — 실제 Claude API로 본문 단락 생성 (3회, 비용 발생)
import sys, json
sys.path.insert(0, ".")
from mywork.write import generate_body_paragraphs
from mywork.review import find_unverified_numbers

with open("mywork/press_data.json", encoding="utf-8") as f:
    data = json.load(f)
본문 = generate_body_paragraphs(data)
for p in 본문:
    print(f"[{p['소주제']}] {p['내용']}")
    print("   근거 없는 숫자:", find_unverified_numbers(p["내용"], data))
data["본문"] = 본문
with open("mywork/press_data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
print("본문 저장")
```

모든 단락의 `근거 없는 숫자`가 `[]`이면 통과입니다. 숫자가 나오면 7절처럼 그 숫자가 어디서 왔는지 설명하고 다시 실행합니다. 슬라이드 18의 체크리스트(표현 반복, 리드문과의 중복)는 사람이 읽고 확인합니다.

## 10. 문제 해결

| 증상 | 원인 | 조치 |
| --- | --- | --- |
| `빈 응답을 건너뛰지 않음` | strip·빈 문자열 검사 누락 | "빈 응답은 건너뛰어줘" 요청 |
| `연결어 규칙 확인` | 연결어를 항목 번호(i)로 고름 | "실제로 추가된 단락 수 기준으로 연결어를 골라줘" 요청 |
| 단락이 "한편, 한편, …"으로 시작 | 모델이 연결어를 붙이고 코드가 또 붙임 | 프롬프트에 "연결어로 시작하지 말 것"이 있는지 확인 |
| `KeyError: '시각자료설명'` | 6차시를 건너뜀 | 2절 준비 코드 또는 "단독 시작" |
| 실제 호출에서 근거 없는 숫자가 계속 나옴 | 모델이 합계·비율을 계산 | 프롬프트의 "새로 계산하지 말 것" 문구 확인, 다시 실행 |
