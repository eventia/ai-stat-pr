## 실습 목표

- 정형 데이터(이미 계산된 지표)와 비정형 데이터(문장)를 각각 정제·표준화하여 하나의 표준 JSON(반정형 데이터) 구조로 만든다.
- 보도자료에 필요한 데이터 항목을 정의하고 필수/선택/참고로 우선순위를 구분해본다.
- 공공데이터포털(data.go.kr) Open API를 실제로 호출해 실시간 데이터를 받아온다.
- 이번에 완성한 표준 JSON 구조는 3차시(NLP)부터 10차시(전체 파이프라인)까지 계속 재사용되는 공통 입력값이 된다.

담당 코드: [../modules/clean.py](../modules/clean.py)(정제·표준화·구조화), [../modules/public_api.py](../modules/public_api.py)(Open API 연동), [../modules/config.py](../modules/config.py)(항목명·단위 설정)
담당 테스트: [../tests/test_ch02_clean.py](../tests/test_ch02_clean.py), [../tests/test_ch02_public_api.py](../tests/test_ch02_public_api.py)

## 0단계. 실습 환경 준비

이미 프로젝트를 한 번 이상 설정했다면 이 단계는 건너뛰어도 됩니다.

```bash
# 가상환경 활성화 (PowerShell)
myvenv\Scripts\Activate.ps1

# 패키지 설치 (최초 1회)
pip install -r requirements.txt
```

프로젝트 루트의 `.env` 파일에 아래 두 키가 들어 있는지 확인합니다.

```
ANTHROPIC_API_KEY=발급받은키
PUBLIC_API_KEY=발급받은키
```

- `PUBLIC_API_KEY`가 아직 없어도 0~5단계는 그대로 진행할 수 있습니다. 6단계에서 직접 발급받습니다.
- `.env`는 `.gitignore`에 포함되어 있어 git에 올라가지 않습니다 (CLAUDE.md 원칙: API 키는 코드에 직접 적지 않고 `.env`에서만 불러온다).

> **Windows 콘솔 한글 깨짐 주의**: PowerShell에서 `python -c "..."`나 `python` 인터랙티브 셸로 한글이 포함된 결과를 출력하면 기본 코드페이지(cp949) 때문에 글자가 깨져 보일 수 있습니다. 이 경우 아래처럼 UTF-8을 강제하고 실행하면 정상적으로 출력됩니다.
> ```powershell
> $env:PYTHONUTF8 = "1"
> ```
> ([../scripts/fetch_public_api_sample.py](../scripts/fetch_public_api_sample.py)처럼 스크립트 안에서 `sys.stdout.reconfigure(encoding="utf-8")`를 넣어도 됩니다.)

## 1단계. 정형·비정형·반정형 데이터 나란히 확인하기

> 개념 참고: 강의안 소주제 1 (lect/CH-02-Content.md 페이지 6~10)

보도자료 원본 자료는 보통 두 가지 형태로 섞여 들어옵니다. 실습을 시작하기 전에 이 둘을 직접 눈으로 비교합니다.

**정형 데이터에 가까운 예시** (이미 계산되어 있는 지표 — 예: 통계청 발표자료에 흔히 함께 실리는 값)

```json
{
  "총거래액": 201250,
  "전월대비증감률": 1.5,
  "전년동월대비증감률": 8.7
}
```

**비정형 데이터 예시** (설명 보고서 원문 발췌 — 공백과 괄호 주석이 섞여 있음)

```
2026년  1월 온라인쇼핑   거래액은   201,250백만원으로   전월대비  1.5%   증가하였음.(주:잠정치) 역대 1월 기준 최대치를 기록함.
```

> 참고: 위 "총거래액" 같은 지표가 항상 API에서 이미 계산되어 오는 것은 아닙니다. 실제로는 개별 판매·신고 기록처럼 집계조차 안 된 원자료로 오는 경우도 있으며, 그 경우 정제만으로는 부족하고 품목별 "집계"까지 필요합니다. 이 확장 시나리오는 5차시와 [../docs/PLAN_raw_data_redesign.md](../docs/PLAN_raw_data_redesign.md)에서 다룹니다. 오늘 2차시에서는 지표가 이미 주어졌다고 가정하고, **정제·표준화·구조화**에 집중합니다.

이 두 원본이 3단계를 거치고 나면 결국 하나의 JSON으로 합쳐지는데, 이 JSON이 바로 강의안이 설명하는 **반정형 데이터**(정형도 비정형도 아닌, 이름표는 있지만 고정된 표는 아닌 형태)입니다. 이번 실습의 최종 결과물도 이 반정형 구조 하나입니다.

## 2단계. 데이터 항목 정의 — 나만의 데이터 딕셔너리 작성해보기

> 개념 참고: 강의안 소주제 2 (lect/CH-02-Content.md 페이지 11~16, 필수/선택/참고 항목 구분과 데이터 딕셔너리 구성요소)

본격적으로 코드를 실행하기 전에, 1단계의 항목들이 각각 무엇을 의미하는지 먼저 문서로 정의해봅니다. 아래 표의 빈칸을 직접 채워보세요.

| 항목명(한글) | 데이터 타입 | 단위 | 정의 | 우선순위(필수/선택/참고) |
| --- | --- | --- | --- | --- |
| 총거래액 | | | | |
| 전월대비증감률 | | | | |
| 전년동월대비증감률 | | | | |
| 공표일자 | | | | |

**작성 힌트**

- 필수 항목: 제목·리드문에 반드시 들어가는 핵심 지표 (예: 총거래액, 증감률)
- 선택 항목: 본문 부연 설명용 부가 지표 (예: 품목별 비중, 지역별 순위)
- 참고 항목: 문맥 이해를 돕는 배경 정보 (예: 자료출처, 조사 대상 기간)

작성이 끝났다면, 실제 프로젝트가 같은 항목을 어떻게 코드로 고정해두었는지 확인합니다.

```python
import sys
sys.path.insert(0, ".")
from modules.config import REQUIRED_FIELDS, INDICATOR_UNITS, PRIMARY_INDICATOR

print("필수 항목:", REQUIRED_FIELDS)
print("항목별 단위:", INDICATOR_UNITS)
print("대표 지표:", PRIMARY_INDICATOR)
```

**확인할 점**

- `REQUIRED_FIELDS`(총거래액, 전월대비증감률, 전년동월대비증감률)가 여러분이 "필수"로 분류한 항목과 일치하는지 비교합니다.
- `INDICATOR_UNITS`에 정의된 단위("억 원", "%")가 여러분이 적은 단위와 같은지 비교합니다.
- [../modules/config.py](../modules/config.py)는 이런 지표명·단위 하드코딩을 한 곳에 모아둔 파일입니다. 실제 서비스에서는 이렇게 항목 정의를 코드 한 곳에서 관리해, 지표명이 바뀔 때 여러 파일을 헤매지 않도록 합니다.

## 3단계. `clean_and_structure()` 직접 실행해보기

> 개념 참고: 강의안 소주제 3 (lect/CH-02-Content.md 페이지 18~23, 정제·표준화·구조화 원칙과 `clean_and_structure` 최소 구현)

[../modules/clean.py](../modules/clean.py)의 `clean_and_structure()` 함수가 1~2단계에서 정의한 항목을 기준으로, 정형 지표와 비정형 원문을 하나의 표준 JSON으로 합치는 역할을 합니다. 아래 코드를 파이썬 인터프리터(`python` 실행 후 붙여넣기)나 임시 스크립트 파일로 직접 실행해봅니다.

```python
import sys, json
sys.path.insert(0, ".")
from modules.clean import clean_and_structure

raw = {
    "제목": "2026년 1월 온라인쇼핑 동향",
    "공표일자": "2026-03-01",
    "자료출처": "공공데이터포털 Open API",
    "계산지표": {
        "총거래액": 201250,
        "전월대비증감률": 1.5,
        "전년동월대비증감률": 8.7,
    },
    "핵심내용": ["온라인쇼핑 거래액 역대 최대 달성"],
    "원문": "2026년  1월 온라인쇼핑   거래액은   201,250백만원으로   전월대비  1.5%   증가하였음.(주:잠정치)",
}

결과 = clean_and_structure(raw)
print(json.dumps(결과, ensure_ascii=False, indent=2))
```

**확인할 점**

- `결과["원문"]`에서 중복 공백이 사라지고, `(주:...)` 괄호 주석이 제거되었는지 확인합니다.
- `백만원` → `백만 원`으로 단위 표기가 통일되었는지 확인합니다.
- `결과["문서정보"]`, `결과["계산지표"]`, `결과["핵심내용"]`이 입력값 그대로 표준 스키마 아래 정리되어 있는지 확인합니다.

정제 전/후를 나란히 비교하면 다음과 같은 차이가 보여야 합니다.

```
정제 전: 2026년  1월 온라인쇼핑   거래액은   201,250백만원으로   전월대비  1.5%   증가하였음.(주:잠정치)
정제 후: 2026년 1월 온라인쇼핑 거래액은 201,250백만 원으로 전월대비 1.5% 증가하였음.
```

## 6단계. 공공데이터포털 Open API 키 발급받기

> 개념 참고: 강의안 소주제 4 (lect/CH-02-Content.md 페이지 24~27)

이제 실시간 공공 데이터를 받아오기 위한 준비를 합니다. `PUBLIC_API_KEY`가 이미 `.env`에 있다면 이 단계는 건너뛰고 7단계로 이동합니다.

1. [data.go.kr](https://www.data.go.kr) 접속 후 회원가입 및 로그인
2. 검색창에서 활용할 API를 검색 (이 실습에서는 "온라인 수집 가격 정보" API를 사용)
3. 해당 API 상세 페이지에서 **활용신청** 클릭 후 활용 목적 등 필요한 항목 입력
4. 승인 후 **마이페이지 → 데이터활용 → 개발계정**에서 인증키(서비스키) 확인
   - 인증키는 "일반 인증키(Encoding)"과 "일반 인증키(Decoding)" 두 가지로 표시됩니다. 둘 중 아무거나 복사해도 됩니다 — [../modules/public_api.py](../modules/public_api.py)가 `urllib.parse.unquote()`로 항상 한 번 디코딩해서 사용하므로 이중 인코딩 문제가 생기지 않습니다.
5. 복사한 값을 `.env` 파일에 저장합니다.

```
PUBLIC_API_KEY=발급받은키
```

> 활용신청 상세보기 페이지의 "참고문서"(활용가이드)도 함께 열어 두면 7단계에서 파라미터 이름(itemCode, startDate 등)을 이해하는 데 도움이 됩니다. 이 프로젝트에는 [../docs/통계청_온라인수집가격정보_OPEN-API활용가이드_v2.2.docx](../docs/통계청_온라인수집가격정보_OPEN-API활용가이드_v2.2.docx)가 참고용으로 포함되어 있습니다.

## 7단계. 실제 Open API 호출해보기

`PUBLIC_API_KEY`가 준비되었다면 아래 데모 스크립트를 실행합니다.

```bash
python scripts/fetch_public_api_sample.py
```

**예상 결과**

```
=== 1) 품목 리스트 조회 (상위 5개) ===
  A01101  쌀
  ...

=== 2) 가격정보 조회 (쌀, 최근 기간) ===
  품목: 쌀(A01101), 전체 N건 중 5건 표시
  - 상품명: 가격원 (가격일자)
  ...
```

**꼭 짚고 넘어갈 점** — 이 API는 이미 계산된 통계치(총거래액 등)를 주지 않고, 개별 상품의 **낱개 판매가격 목록**만 돌려줍니다. 즉 API 응답 자체는 아직 "비정형에 가까운 원자료"이며, 평균가격 같은 지표는 우리가 직접 계산해야 합니다 (이 계산은 5차시 `modules/price_stats.py`가 담당합니다). 2차시에서는 이 원자료를 받아오는 연동 자체에 집중합니다.

응답 형식과 관련해 실제로 발급받아 확인한 주의사항 3가지:

1. **응답이 JSON이 아니라 XML**입니다 → `xml.etree.ElementTree`(표준 라이브러리)로 파싱합니다.
2. 인증키를 `requests`의 `params`에 넣으면 자동으로 한 번 URL 인코딩되므로, 이미 인코딩된 키를 그대로 넣으면 **이중 인코딩 오류**(`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`)가 납니다 → 사용 전 `unquote()`로 미리 디코딩해 둡니다.
3. `startDate`/`endDate`는 `"20260101"`(YYYYMMDD, 하이픈 없음) 형식이며, 조회 기간은 최대 30일, 종료일은 오늘로부터 최소 2일 전(D-2)까지만 허용됩니다.

## 10단계. 완성도 점검

방금 만든 표준 JSON을 아래 기준으로 스스로 점검합니다.

1. `문서정보`, `계산지표`, `핵심내용`, `원문` 네 항목이 모두 채워져 있는가
2. `원문`에서 중복 공백·괄호 주석이 제거되고 단위 표기가 통일되었는가
3. 개인정보(연락처, 주민등록번호 등)가 섞여 있었다면 마스킹되었는가
4. API에서 받은 원본 수치(평균가격 등)와 `계산지표`의 수치가 1대1로 일치하는가
5. 2단계에서 정의한 필수 항목이 모두 이 구조 안에 들어 있는가
6. 이 구조만으로 AI가 리드문을 작성하는 데 충분한 정보가 담겨 있는가

## 12단계. 3차시부터 이어받을 표준 데이터 저장 ★가장 중요★

지금까지는 API 예시나 짧은 문장으로 개념을 확인했습니다. 이제 **3~10차시가 계속 이어받아 쓸 실제 예제 데이터**를 만들어 `data/processed/press_data.json`에 저장합니다. 이 파일이 이번 2차시 실습의 핵심 산출물입니다.

아래 원문은 이 프로젝트의 실제 샘플 원자료([data/raw/온라인쇼핑동향_2026_01.xlsx](../data/raw/온라인쇼핑동향_2026_01.xlsx))에 들어있는 문장과 동일합니다 — 7차시에서 이 xlsx 파일을 직접 읽을 때 서로 같은 내용인지 대조할 수 있습니다.

```python
import sys, json, os
sys.path.insert(0, ".")
from modules.clean import clean_and_structure

raw = {
    "제목": "2026년 1월 온라인쇼핑 동향",
    "공표일자": "2026-03-01",
    "자료출처": "공공데이터포털 Open API",
    "계산지표": {
        "총거래액": 201250,
        "전월대비증감률": 1.5,
        "전년동월대비증감률": 8.7,
    },
    "핵심내용": ["온라인쇼핑 거래액 역대 최대 달성"],
    "원문": (
        "2026년 1월 온라인쇼핑 거래액은 201,250억 원으로 전월 대비 1.5% 증가하였다. "
        "전년동월대비로는 8.7% 증가한 수치이다. 이는 역대 1월 기준 최대치를 기록한 것이다. "
        "모바일쇼핑 거래액 비중은 전체의 78%를 차지하며 꾸준한 증가세를 보이고 있다."
    ),
}

data = clean_and_structure(raw)

os.makedirs("data/processed", exist_ok=True)
with open("data/processed/press_data.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
print("저장 완료: data/processed/press_data.json")
```

**확인할 점**

- `data/processed/press_data.json` 파일이 실제로 생성되었는지 파일 탐색기나 `cat`(PowerShell은 `Get-Content`)으로 열어 확인합니다.
- 이 원문은 이미 정제된 문장이라 `clean_and_structure`를 거쳐도 거의 그대로지만, 앞으로 이 파일을 열 때마다 `문서정보`/`계산지표`/`핵심내용`/`원문` 네 필드가 있다는 것을 기억해 둡니다. 3차시부터는 이 네 필드 위에 `NLP분석결과`, `통계해석결과`, `시각자료설명`, `헤드라인`, `본문`, `최종본`, `검수결과` 필드가 차례로 쌓입니다.
