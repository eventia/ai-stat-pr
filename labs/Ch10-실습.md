## 2단계. (실제 비용 발생) 실제 xlsx로 전체 파이프라인 실행하기

> 개념 참고: 강의안 페이지 11 (실행 코드)

```bash
python main.py
```

`main.py`는 기본으로 `data/raw/온라인쇼핑동향_2026_01.xlsx`를 입력으로 사용합니다. `.env`의 `ANTHROPIC_API_KEY`가 있으면 바로 실행됩니다.

**실행되는 6단계** ([main.py](../main.py) 코드 그대로)

```python
def main(파일경로: str) -> dict:
    raw_data = load_input(파일경로)                              # 1. 입력 (7차시)
    data = clean_and_structure(raw_data)                         # 2. 정제 (2차시)
    data = analyze_document(data["원문"], data)                  # 3. NLP 분석 (3차시, 참고용)
    data = add_calculated_indicators(data)                       # 3. 계산 (5차시)
    if "품목별지표" in data or "월별이력" in data:
        data["시각자료설명"] = build_visual_descriptions(data)   # 3. 그래프 (6차시)
    data["요약결과"] = generate_summary(data)                    # 3-1. 참고 요약 (4차시)
    data["헤드라인"] = generate_headline_set(data)                # 4. 헤드라인 (7차시)
    data["본문"] = generate_body_paragraphs(data)                 # 4. 본문 (8차시)
    data["최종본"] = unify_style(assemble_full_text(data))        # 5. 문체 통일 (9차시)
    data["검수결과"] = {                                          # 5. 검수 (9차시)
        "표기오류검사": check_formatting_errors(data["최종본"]),
        "수치교차검증": cross_check_all_numbers(data["최종본"], data),
        "AI감수지적사항": review_press_release(data["최종본"], data),
    }
    save_final_document(data)                                    # 6. 저장 (10차시)
    return data
```

이 xlsx에는 "이력" 시트가 없으므로, `역대최대여부`는 자동 계산되지 않고 `add_calculated_indicators`가 기본값(`False`)을 씁니다 — 7차시 1단계에서 이미 확인한 내용입니다. 그 결과 이번 실행에서는 "역대 최대치 경신"이 특이점 목록에 나타나지 않을 수 있습니다. "이력" 시트가 자동 계산을 실제로 발동시키는 모습은 1단계의 두 번째 pytest에서 이미 확인했습니다.

**출력 확인**

```python
print("=== 최종 보도자료 ===")
print(결과["최종본"])
print("수치 교차 검증 통과 여부:", 결과["검수결과"]["수치교차검증"]["통과"])
print("표기 오류 검사:", 결과["검수결과"]["표기오류검사"])
```

## 완성도 점검 (과정 전체 최종 점검)

1. 원자료 입력부터 최종본 저장까지 사람의 개입 없이 한 번에 실행되는가
2. 최종본의 모든 수치가 원본 데이터와 정확히 일치하는가 (`수치교차검증.통과 == True`)
3. 실행 중 오류가 발생했을 때 `logs/pipeline.log`로 원인을 추적할 수 있는가
4. 자동 생성된 최종본에 대해 담당자의 최종 승인 절차가 여전히 필요하다는 것을 이해했는가
5. API 키 관리(`.env`), 개인정보 마스킹(2차시) 등 보안 원칙이 파이프라인 전체에 유지되고 있는가

## 이 시스템이 아직 자동화하지 못한 것 (정직한 마무리)

10차시를 완주하면 "완전 자동화 시스템"이라는 표현을 쓰고 싶어지지만, 직접 9차시 3단계와 5차시 5단계에서 확인했듯 아직 남아있는 한계가 있습니다.

- **파생 수치 검증**: AI가 문장 안에서 스스로 계산한 숫자(예: 품목 비중 합계)는 `cross_check_all_numbers`가 불일치로 잡아내지만, 자동으로 고쳐주지는 않습니다 — 사람이 확인하거나 `stats.py`에 그 계산을 추가해야 합니다.
- **지표명 자동 추출의 한계**: `add_calculated_indicators`가 해석문장의 주어를 제목의 마지막 단어로 추출하는데, 제목이 "~동향"으로 끝나면 "동향은 ~을 기록하였다"처럼 어색한 문장이 나올 수 있습니다(5차시 5단계 참고).
- **다른 통계표로의 재사용은 절반만 가능**: 검증·문체통일·본문확장(`modules/review.py`, `expand_to_paragraph`)은 지표명에 의존하지 않아 그대로 재사용되지만, `REQUIRED_FIELDS`나 `load_input`의 컬럼명 같은 계산·입력 부분은 통계표가 바뀌면 새로 작성해야 합니다(실제로 이 프로젝트에서 `main_price.py`/`main_practice.py`를 만들 때 `modules/price_stats.py`·`modules/pet_stats.py`를 별도로 새로 작성해야 했던 것이 그 증거입니다).
- **꺾은선그래프의 `line` 분기와 `generate_table_description`**: 이번 실습(6차시)에서 실제로 연결해 보았지만, `main.py`가 기본으로 쓰는 xlsx에는 "이력" 시트가 없어 실행할 때마다 항상 켜지지는 않습니다. `generate_table_description`(표 전체를 문장으로 요약)은 아직 `build_visual_descriptions`에서 호출되지 않는 별도 함수로 남아있습니다.

자동화는 반복 작업의 부담을 줄여주는 도구일 뿐, 최종 책임은 항상 담당자에게 있습니다. 10차시까지 완주한 여러분은 이제 "계산은 정밀한 프로그램이, 문장은 생성형 AI가" 담당하는 보도자료 자동화 시스템을 직접 설계하고, 그 한계까지 정확히 짚어낼 수 있는 역량을 갖추었습니다. 수고하셨습니다.
