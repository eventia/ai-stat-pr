### 페이지 08. 모듈별 함수 정리

지금까지 만든 핵심 함수 목록

| 단계 | 함수명 |
| --- | --- |
| 입력 | `load_input(파일경로)` |
| 정제 | `clean_and_structure(raw)` |
| NLP 분석 (참고용) | `analyze_document(text, data)` |
| 참고용 요약 (선택) | `generate_summary(data)` — 사실 확정에는 쓰이지 않으며, `제목후보`만 헤드라인 프롬프트에 참고용으로 전달됨 |

| 원자료 집계 (표본 데이터 전용) | `aggregate_sample_sales(표본매출)`, `build_indicators(표본매출, 이력, current_ym)` — 이미 계산된 표가 아니라 집계 전 개별 신고 데이터에서 시작할 때 사용 |
| 그래프·설명 통합 | `build_visual_descriptions(data)` (내부에서 `generate_chart_description` 호출) |
| 헤드라인 생성 | `generate_headline_set(data)` (내부에서 `build_headline_prompt` 호출) |
| 본문 생성 통합 | `generate_body_paragraphs(data)` (내부에서 `expand_to_paragraph` 반복 호출) |
| 문체 통일·자동 검수 | `assemble_full_text(data)`, `unify_style(text)`, `check_formatting_errors(text)`, `cross_check_all_numbers(text, data)` |
| AI 감수 | `review_press_release(text, data)` |
| 저장 | `save_final_document(data)` |

> **[Note]** 전체 시스템을 만들기 전에, 지금까지 각 차시에서 만든 함수들을 한 번에 정리해보는 것이 중요합니다. 이 표가 곧 오늘 작성할 메인 스크립트의 설계도가 됩니다. 표를 순서대로 훑어보시면, 입력부터 저장까지 열네 개 남짓한 함수가 각 차시에서 하나씩 만들어졌다는 것을 확인할 수 있습니다. 특히 "참고용 요약"과 "NLP 분석" 두 줄에는 "참고용"이라는 표시가 붙어 있는데, 이 두 결과는 최종 보도자료의 숫자나 사실을 결정하는 데는 쓰이지 않고 AI가 표현을 구상할 때 참고하는 보조 자료라는 점을 다시 한번 기억해 주세요. 사실 확정은 언제나 계산 단계의 결과가 담당합니다.

### 페이지 09. 메인 실행 스크립트 설계

main.py 전체 구조 개요

```python
def main(파일경로: str):
    # 1. 입력
    raw_data = load_input(파일경로)
    # 2. 정제
    data = clean_and_structure(raw_data)
    # 3. NLP 분석 + 계산 + 그래프 설명 (수치는 프로그램이 계산, AI는 문장만 담당)
    data = analyze_document(data["원문"], data)
    data = add_calculated_indicators(data)
    if "품목별지표" in data or "월별이력" in data:
        data["시각자료설명"] = build_visual_descriptions(data)
    # 4. AI 작성 (참고용 요약 + 헤드라인 + 본문)
    data["요약결과"] = generate_summary(data)
    data["헤드라인"] = generate_headline_set(data)
    data["본문"] = generate_body_paragraphs(data)
    # 5. 검수 (자동 수치·표기 교차 검증 + AI 감수, 처음에 배운 3단계 안전장치)
    data["최종본"] = unify_style(assemble_full_text(data))
    data["검수결과"] = {
        "표기오류검사": check_formatting_errors(data["최종본"]),
        "수치교차검증": cross_check_all_numbers(data["최종본"], data),
        "AI감수지적사항": review_press_release(data["최종본"], data),
    }
    # 6. 저장
    save_final_document(data)
    return data
```

> **[Note]** 지금까지 각 차시에서 배운 함수들을 순서대로 호출하는 하나의 main 함수로 정리했습니다. 파일 경로 하나만 입력하면 이 함수 안에서 정제, 분석, 계산, 작성, 검수, 저장이 순차적으로 자동 실행됩니다. 코드를 자세히 보시면 몇 가지 설계 포인트가 있습니다. 첫째, 그래프 생성 조건이 "품목별지표가 있거나 월별이력이 있으면"으로 되어 있는데, 이렇게 두 조건을 or로 묶어야 품목별 데이터가 없어도 월별 이력만 있으면 꺾은선그래프가 생성될 수 있습니다. 둘째, 계산 단계 바로 다음에 generate_summary를 호출해서 요약결과를 참고용으로 만들어두고, 이 결과가 뒤이은 generate_headline_set 안에서 제목 아이디어로 참고됩니다. 셋째, 검수 단계에서는 표기오류검사, 수치교차검증, AI감수지적사항 이렇게 세 가지를 모두 검수결과에 담습니다. 이 세 가지가 바로 처음부터 강조해온 "계산은 프로그램이, 검증은 교차 대조로"라는 3단계 안전장치가 최종 시스템에 실제로 반영된 모습입니다. AI 감수 하나만 믿는 것이 아니라, 자동 수치·표기 검증과 AI 감수를 함께 돌려야 안전하다는 것을 꼭 기억해 주세요.

```python
def save_final_document(data: dict):
    os.makedirs("output", exist_ok=True)  # output 폴더가 없으면 FileNotFoundError 발생 방지
    with open(f"output/{data['문서정보']['제목']}.txt", "w", encoding="utf-8") as f:
        f.write(data["최종본"])
    # 실무에서는 python-docx, hwpx 라이브러리 등을 활용해
    # 공식 보도자료 서식(제목, 로고, 표, 그래프 삽입)에 맞춰 최종 변환
```

> **[Note]** 이번 실습에서는 완성된 텍스트를 파일로 저장하는 기본 형태까지 다룹니다. output 폴더를 미리 만들고, 문서정보의 제목을 파일명으로 삼아 최종본 텍스트를 UTF-8 인코딩으로 저장합니다. 실제 현업에서는 이 텍스트를 기관의 공식 보도자료 양식, 예를 들어 hwpx나 docx 같은 형식에 맞추어 표와 그래프 이미지까지 함께 삽입하는 후처리 단계가 추가로 필요합니다. 오늘 우리가 만든 것은 그 전 단계, 즉 검수까지 끝난 순수한 텍스트를 만드는 부분까지입니다.

향후 확장 가능한 방향

- 다른 통계표 적용: 온라인쇼핑 동향 외에 물가, 수출입 등 다른 통계에도 동일한 파이프라인 재사용
- 배치 처리: 여러 개의 파일을 한 번에 처리하는 반복 실행 기능 추가
- 웹 인터페이스 연동: 담당자가 파일을 업로드하면 결과를 웹 화면에서 확인하는 형태로 발전

이 시스템의 세 가지 진입점 비교

| 진입점 | 원자료 상태 | "계산" 단계가 하는 일 | 재사용 여부 |
| --- | --- | --- | --- |
| `main.py` | 이미 계산된 표 (온라인쇼핑 동향) | 특이점 판별·해석문장 생성만 | — |
| `main_price.py` | 진짜 원자료 (공공데이터포털 개별 상품 가격) | 평균가격·증감률 계산부터 전부 | 그래프·헤드라인·본문·검수 재사용, 계산 로직만 새로 작성 |
| `main_practice.py` | 합성 원자료 (표본 사업체 매출 신고) | 품목별 집계·증감률 계산부터 전부 | 위와 동일한 원칙, 계산 로직만 새로 작성 |

> **[Note]** 지금까지 만든 시스템은 하나의 통계표를 기준으로 설계되었지만, 표준 데이터 구조인 JSON을 그대로 유지한다면 다른 통계 항목이나 여러 파일을 한 번에 처리하는 형태로도 확장할 수 있습니다. 다만 정확히 짚고 넘어갈 부분이 있습니다. 이 프로젝트에는 실제로 세 개의 진입점이 있는데, 서로 다른 것은 통계 항목이 아니라 원자료가 어디까지 가공되어 있는가입니다. main.py는 이미 계산이 끝난 표를 받아서 특이점 판별과 해석문장 생성만 담당합니다. main_price.py는 공공데이터포털의 개별 상품 가격이라는 진짜 원자료를 받아서 평균가격 계산부터 전부 직접 수행합니다. main_practice.py는 표본 사업체의 매출 신고라는 합성 원자료를 받아서 품목별 집계와 증감률 계산부터 전부 직접 수행합니다. 이 세 예시 모두 검증·문체통일·AI감수를 담당하는 모듈과 본문을 확장하는 함수는 전혀 수정 없이 그대로 재사용합니다. 반면 "계산" 단계, 즉 무엇을 원자료로 볼 것인지와 무엇을 어떻게 집계할 것인지는 통계표의 구조에 맞춰 매번 새로 작성해야 했습니다. 그래서 정확히 말하면 "표준 구조만 유지하면 완전히 같은 코드로 재사용된다"기보다는, "검증과 작성 단계는 재사용하고, 계산 단계만 원자료 형태에 맞춰 새로 작성한다"는 것이 이 시스템을 다른 통계표로 확장할 때의 현실적인 원칙입니다.

### 페이지 16. 운영 시 주의사항, 보안 체크리스트 최종 재확인

시스템 운영 전 최종 점검 (처음에 배운 보안 원칙 재확인)

1. API 비밀키가 .env로 안전하게 관리되고 있는가
2. 미공개 통계 데이터가 외부로 유출될 경로가 없는가
3. 개인정보 마스킹 전처리가 파이프라인에 포함되어 있는가
4. 자동 생성된 최종본에 대해 사람의 최종 승인 절차가 남아있는가

> **[Note]** 아무리 자동화가 잘 되어 있어도, 처음에 배운 보안 원칙과 사람의 최종 확인 절차는 예외 없이 유지되어야 합니다. API 비밀키가 .env로 안전하게 관리되고 있는지, 미공개 통계 데이터가 외부로 유출될 경로가 없는지, 개인정보 마스킹 전처리가 파이프라인에 포함되어 있는지, 그리고 무엇보다 자동 생성된 최종본에 대해 사람의 최종 승인 절차가 여전히 남아있는지 반드시 확인해야 합니다. 자동화는 반복 작업의 부담을 줄여주는 도구일 뿐, 최종 책임은 항상 담당자에게 있다는 점을 다시 한번 강조하고 싶습니다.

### 페이지 17. 정리하기

1. 전체 파이프라인의 6단계 구조를 하나의 main 함수로 통합
  - 입력, 정제, 계산, AI 작성, 검증, 저장까지 여섯 단계를 하나의 실행 스크립트로 연결해서, 원자료 파일 하나만 입력하면 검수까지 끝난 보도자료가 자동으로 완성되는 시스템을 만들었습니다.
  - 실제로 이 시스템을 실행해 결과를 확인하고, 에러 처리와 로깅을 더해 안정적으로 운영할 수 있는 형태로 다듬었습니다.
2. "계산은 프로그램이, 문장은 생성형 AI가" 원칙의 완성
  - 과정 전체에서 강조해 온 원칙대로, 모든 수치 계산은 파이썬 함수가 전담하고 생성형 AI는 검증된 숫자를 바탕으로 문장만 작성하도록 설계했습니다.
  - 자동 수치·표기 검증과 AI 감수라는 3단계 안전장치를 최종 시스템에도 그대로 반영해, 사람이 최종 승인하기 전 오류를 최대한 걸러내도록 만들었습니다.
3. 다른 통계표로의 확장과 운영상 주의사항
  - 표준 데이터 구조(JSON)를 유지하면 검증·작성 단계는 그대로 재사용하고, 계산 단계만 원자료 형태에 맞춰 새로 작성하면 다른 통계표에도 이 시스템을 적용할 수 있음을 확인했습니다.
  - 자동화가 잘 되어 있더라도 보안 원칙과 사람의 최종 승인 절차는 예외 없이 유지해야 한다는 점을 마지막으로 다시 한번 강조했습니다.
  - 수고하셨습니다. 지금까지의 모든 차시를 거쳐, 여러분은 "계산은 정밀한 프로그램이, 문장은 생성형 AI가" 담당하는 안전하고 정확한 보도자료 자동화 시스템을 스스로 설계하고 구현할 수 있는 역량을 갖추게 되었습니다.
