# 페이지 03. 도입

통계 자료를 바탕으로 보도자료나 리포트를 작성해 보신 적이 있으신가요? 복잡한 표에서 필요한 수치를 일일이 확인하고, 전월이나 전년 대비 증감률을 계산한 뒤, 이를 자연스러운 문장으로 옮겨 적는 과정은 생각보다 많은 시간과 정성이 들어갑니다. 숫자 하나, 단위 하나라도 틀릴까 봐 몇 번이고 눈으로 검수해야 하죠.
최근에는 이러한 반복적인 수치 가공과 문장 작성 업무를 AI가 보조해 주는 기술이 주목받고 있습니다. 사람이 일일이 문장을 쓰는 대신 AI가 수치의 패턴을 읽고 초안을 작성해 주면, 담당자는 검수와 판단이라는 더 중요한 일에 집중할 수 있게 되는 것입니다.
이 과정에서 '과연 AI가 쓴 숫자를 온전히 믿어도 될까?', '입력한 중요한 데이터가 외부에 유출되지는 않을까?' 하는 걱정이 앞서기 마련입니다. 우리는 종종 국가와 세계적인 컴퓨터 기업들이 치명적인 오류를 내거나 해킹사고를 당하는 일들을 뉴스를 통해 접하곤 합니다. 뉴스에 나오지 않는 일들까지 조사해본다면 엄청나게 많은 사건과 사고들이 있는 것이 현실입니다. 이런 현실속에서 'AI는 나보다 똑똑하니, AI가 해준 답은 틀림없이 맞을거야'라는 생각은 순진한 생각일 수 있습니다. 의심하고, 한번 더 검토해서 잘못된 결과가 나오지 않도록 하는 것과 잘못된 결과가 나오더라도 그것을 파악해 낼수 있는 이성적이고 합리적인 접근이 필요합니다. 
이번 과정은 프로그래밍이나 AI에 대한 전문 지식이 없더라도 누구나 쉽게 따라 할 수 있도록 구성되었습니다. AI를 활용해 수치 계산의 번거로움을 줄이고, 입력한 정보가 외부에 유출되거나 학습되지 않는 안전한 환경 속에서 통계 보도자료 초안을 손쉽게 만들어내는 방법, 그 유용한 첫걸음을 지금부터 함께 시작해 보겠습니다.

### 페이지 06. 현행 보도자료 작성 방식의 한계 및 문제점

수작업 보도자료 작성 시 발생하는 4가지 주요 어려움

- 수치 산출의 번거로움: 대용량 통계표 가공 시, 단위나 수식을 일일이 확인해야 하여 오류 위험 존재
- 문장 작성의 부담: 단순히 숫자만 나열하는 것을 넘어, 독자가 이해하기 쉬운 문맥을 구성하는데 많은 시간 소요
- 검수의 피로도: 퍼센트(%)와 퍼센트포인트(%p)의 구분, 단락 간 숫자 일치 여부를 눈으로 검수하는 부담
- 시간적 압박: 정해진 배포 시점까지 다각도의 깊이 있는 분석문을 작성하기에 시간이 부족함

> **[Note]** 통계 보도자료를 수작업으로 작성할 때 실무자들이 겪는 어려움은 크게 네 가지입니다. 먼저 수치 산출의 번거로움인데요, 대용량 통계표를 다루다 보면 단위를 억 원으로 할지 조 원으로 할지, 증감률 계산식을 어떻게 적용할지 하나하나 확인해야 해서 실수할 위험이 항상 존재합니다. 둘째는 문장 작성의 부담입니다. 단순히 숫자만 나열해서는 안 되고, 독자가 이해하기 쉽도록 맥락을 짜임새 있게 구성해야 하는데 여기에 많은 시간이 걸립니다. 셋째는 검수의 피로도입니다. 특히 퍼센트(%)와 퍼센트포인트(%p)를 구분하는 문제, 그리고 앞 문단과 뒤 문단에서 같은 숫자를 다르게 쓰지 않았는지 사람이 눈으로 하나하나 대조해야 하는 부담이 큽니다. 마지막으로 시간적 압박인데, 보도자료는 정해진 배포 시점이 있기 때문에 여러 각도에서 깊이 있게 분석할 여유가 부족한 경우가 많습니다. 오늘부터 배울 내용은 바로 이 네 가지 어려움을 AI와 프로그램의 조합으로 어떻게 해결할 것인가에 대한 이야기입니다.

### 페이지 07. AI 기반 보도자료 자동화 5단계 파이프라인

5단계 파이프라인 구조

1. 수집: 통계 시스템 및 문서 내 필요 수치 데이터 자동 수집
2. 정제: AI 처리가 용이한 표준 데이터 형태로의 정제 및 정리
3. 분석: 증감률, 비중, 역대 최고, 최저치 등 주요 변화 지표 연산
4. 작성: AI 모델 활용 제목, 요약문 및 본문 초안 작성
5. 검수: 원본 데이터 대조를 통한 수치 자동 검증 및 문체 교정

> **[Note]** 방금 살펴본 문제들을 해결하기 위해 이 과정 전체에서 다룰 5단계 자동화 파이프라인을 소개하겠습니다. 1단계는 수집으로, 통계 시스템이나 문서에서 필요한 수치 데이터를 자동으로 가져오는 단계입니다. 2단계는 정제로, 수집된 자료를 AI가 처리하기 좋은 표준 데이터 형태로 깔끔하게 다듬는 과정입니다. 3단계는 분석입니다. 증감률, 비중, 역대 최고·최저치 같은 주요 변화 지표를 실제로 계산하는 단계죠. 4단계는 작성으로, 앞서 계산된 결과를 바탕으로 AI 모델이 제목과 요약문, 본문 초안을 작성합니다. 마지막 5단계는 검수입니다. AI가 만든 문장 속 숫자를 원본 데이터와 다시 한번 자동으로 대조하고, 문체까지 교정해서 최종본을 완성합니다. 앞으로 이어질 여러 차시에 걸쳐 우리가 배우는 모든 내용은 결국 이 다섯 단계 각각을 실제로 어떻게 코드로 구현하느냐에 대한 이야기라고 보시면 됩니다.

### 페이지 08. 수치 정확성(정합성)을 확보하는 3단계 안전장치

3단계 안전장치 구조

1. 1단계 (정확한 연산 전담): 모든 숫자 계산(증감률, 비중 등)은 컴퓨터 프로그램 알고리즘이 직접 수행하며, AI에게 계산을 맡기지 않음
2. 2단계 (검증된 수치 제공): 이미 완벽하게 계산된 결과 숫자만을 AI에게 입력하여 문장을 작성하도록 유도
3. 3단계 (자동 교차 검증): AI가 만들어낸 문장 속의 숫자를 원본 데이터와 1대1로 비교하여 틀린 부분이 없는지 최종 확인

> **[Note]** 이 과정 전체를 관통하는 가장 중요한 원칙 하나를 짚고 넘어가겠습니다. 바로 수치 정확성을 확보하는 3단계 안전장치입니다. 1단계는 정확한 연산 전담 원칙으로, 증감률이나 비중 같은 모든 숫자 계산은 컴퓨터 프로그램 알고리즘이 직접 수행하고 AI에게는 계산을 절대 맡기지 않습니다. 2단계는 검증된 수치 제공 원칙입니다. AI에게는 이미 프로그램이 완벽하게 계산을 끝낸 결과 숫자만 입력으로 주고, 그 숫자를 바탕으로 문장만 작성하도록 유도합니다. 3단계는 자동 교차 검증입니다. AI가 아무리 검증된 숫자만 받았다고 해도 문장을 쓰는 과정에서 실수로 다른 숫자를 쓸 수 있기 때문에, 완성된 문장 속의 모든 숫자를 원본 데이터와 하나하나 대조해서 틀린 부분이 없는지 마지막으로 확인합니다. '계산은 프로그램이, 검증된 숫자만 AI에게, 그리고 다시 한번 교차 검증'이라는 이 원칙은 이후 여러 차시에 걸쳐 실제 코드로 구현할 것이고, 이번 과정 전체에서 가장 자주 반복해서 강조할 핵심 원칙이니 꼭 기억해 두시기 바랍니다.

### 페이지 09. 표준 통계 보도자료의 핵심 구성 요소

구성 요소 블록

- 제목 및 부제: 핵심 지표의 변화를 한눈에 보여주는 요약 문구
- 리드문(첫 문단): 6하 원칙에 따라 핵심 내용과 전년 대비 변화를 요약한 문장
- 세부 본문: 분야별, 항목별 동향을 논리적인 단락으로 나누어 설명
- 시각자료 설명문: 표나 그래프가 의미하는 추세와 특징을 설명하는 문구

> **[Note]** 이제 우리가 최종적으로 만들어낼 결과물, 즉 통계 보도자료 자체가 어떤 요소들로 구성되는지 살펴보겠습니다. 먼저 제목과 부제가 있는데, 핵심 지표의 변화를 한눈에 보여주는 요약 문구입니다. 다음으로 리드문, 즉 첫 문단이 있습니다. 이건 육하원칙에 따라 핵심 내용과 전년 대비 변화를 압축해서 요약한 문장입니다. 그다음은 세부 본문인데, 분야별이나 항목별 동향을 논리적인 단락으로 나누어 설명하는 부분입니다. 마지막으로 시각자료 설명문이 있는데, 표나 그래프가 담고 있는 추세와 특징을 글로 풀어서 설명하는 문구입니다. 결국 우리가 만드는 AI 시스템은 이 네 가지 요소, 즉 제목·부제, 리드문, 본문, 시각자료 설명문을 순서대로 자동 생성하는 시스템이라고 이해하시면 됩니다. 이 구성은 이후 여러 차시에 걸쳐 순서대로 하나씩 직접 만들어보게 됩니다.

### 페이지 10. 보도자료 배포 절차와 공표 전 보안 통제

배포 프로세스

1. 통계 자료 가공
2. 외부 유출이 차단된 환경에서 AI 초안 작성
3. 작성자 직접 검수 및 승인
4. 사전 배포 (엠바고)
5. 공식 공표

> **[Note]** 통계 보도자료는 단순한 문서가 아니라 정해진 공표 시점까지 철저하게 보안이 유지되어야 하는 사전 보안 대상 문서입니다. 전체 배포 프로세스를 보면, 먼저 통계 자료를 가공하고, 외부로 유출될 위험이 차단된 안전한 환경에서 AI가 초안을 작성합니다. 그다음 작성자가 직접 그 초안을 검수하고 승인하는 절차를 거치고, 정식 공표 이전에 관계 기관에만 미리 배포하는 엠바고 단계를 거친 뒤에야 비로소 공식적으로 공표됩니다. 여기서 꼭 기억하셔야 할 것은, AI 도구를 아무리 적극적으로 활용하더라도 최종 확인과 승인은 반드시 사람이 직접 수행해야 한다는 점입니다. 그리고 배포 전 미공개 데이터가 외부망으로 새어 나가지 않도록, 작성 과정 자체가 안전하게 격리된 환경에서 이루어져야 한다는 점도 함께 기억해 주세요.

### 페이지 11. AI 기반 보도자료 작성 전체 시스템 구조도

전체 시스템 아키텍처

1. 입력: 엑셀, PDF, 문서 자료
2. 데이터 정제 모듈
3. 수치 계산 프로그램 (계산 완료 데이터 확보)
4. Claude Code AI (문장 작성 지침 전달, 보도자료 초안 작성)
5. 수치 교차 검증 모듈
6. 최종 문서 저장 (hwpx, PDF)

> **[Note]** 지금까지 설명한 내용을 하나의 그림으로 정리하면 이렇습니다. 이번 교육과정을 통해 함께 만들어갈 전체 시스템 구조도인데요, 먼저 엑셀이나 PDF, 문서 형태의 원본 자료가 입력되고, 이 자료는 데이터 정제 모듈을 거쳐 깔끔하게 정리됩니다. 그다음 수치 계산 프로그램이 증감률 같은 지표를 정확하게 계산해서 '계산 완료' 상태의 데이터를 확보하고요, 이 데이터를 Claude Code 같은 AI에게 전달해서 문장 작성 지침과 함께 보도자료 초안을 작성하도록 합니다. 작성된 초안은 수치 교차 검증 모듈을 거쳐 원본과 대조되고, 마지막으로 hwpx나 PDF 같은 최종 문서 형태로 자동 저장됩니다. 이 여섯 단계, 즉 입력, 정제, 계산, AI 작성, 검증, 저장이 바로 우리가 앞으로 전체 과정에 걸쳐서 하나씩 직접 코드로 구현해 나갈 전체 그림입니다.

    "전월대비증감률": 1.5,
    "전년동월대비증감률": 8.7
  },
  "핵심내용": ["온라인쇼핑 거래액 역대 최대 달성"]

> **[Note]** 방금 본 시스템 구조도에서 각 단계, 즉 정제 모듈, 계산 프로그램, AI 작성 모듈, 검증 모듈은 서로 완전히 다른 프로그램인데 어떻게 데이터를 주고받을까요? 이때 필요한 것이 바로 표준 데이터 양식이고, 이 과정에서는 JSON이라는 형식을 사용합니다. 화면에 보이는 예시처럼, '문서정보'라는 이름표 아래에 제목과 공표일자를 담고, '계산지표'라는 이름표 아래에 총거래액이나 증감률 같은 계산된 숫자를 담습니다. 이렇게 각 데이터에 명확한 이름을 붙여서 정돈해두면 사람이 보기에도 이해하기 쉽고, 프로그램끼리 데이터를 주고받기도 훨씬 수월해집니다. 컴퓨터는 이렇게 부호로 명확하게 구분된 덩어리로 데이터를 전달받는 것을 가장 좋아하기 때문에, 앞으로 우리가 만들 모든 모듈은 이 JSON 형태의 표준 데이터를 입력받고 출력하는 방식으로 설계할 것입니다.

### 페이지 14. AI, 머신러닝, 딥러닝, 생성형 AI의 관계

포함 관계 동심원 구조

- 인공지능: 기계가 인간의 행동을 모방 (기존 프로그래밍 포함)
- 기계학습: 인공지능 중 코드로 명시하지 않은 동작을 데이터를 이용해 스스로 학습
- 딥러닝: 기계학습 중 DNN(Deep Neural Network)을 이용한 분야
- 생성형 AI, 대화형 모델(LLM): 문맥을 이해하고 새로운 글이나 이미지를 만들어 내는 기술

> **[Note]** 이제부터는 AI 기술 자체에 대한 기본 개념을 정리하겠습니다. 먼저 이 네 가지 용어, 인공지능, 머신러닝, 딥러닝, 생성형 AI가 서로 어떤 관계인지 이해하는 것이 중요합니다. 가장 넓은 개념인 인공지능은 기계가 인간의 행동을 모방하는 모든 것을 가리키며, 여기에는 기존의 전통적인 프로그래밍 방식도 포함됩니다. 그 안에 머신러닝이 있는데, 이건 사람이 규칙을 일일이 코드로 정해주지 않아도 데이터를 통해 기계가 스스로 규칙을 학습하는 기술입니다. 머신러닝 중에서도 사람의 뇌 신경망을 모방한 딥 뉴럴 네트워크, 즉 DNN을 이용하는 분야가 딥러닝입니다. 그리고 이 딥러닝 기술이 발전해서 나온 것이 바로 생성형 AI, 즉 우리가 쓸 대화형 모델(LLM)입니다. 이 모델은 단순히 분류하거나 예측하는 것을 넘어, 문맥을 이해하고 완전히 새로운 글이나 이미지를 만들어낼 수 있습니다. 오늘 이후 우리가 계속 사용할 Claude 같은 모델이 바로 이 생성형 AI에 해당한다는 것을 기억해 주세요.

### 페이지 15. 컴퓨터가 사람의 말을 이해하는 기술(자연어 처리)의 발전 과정

4단계 발전 과정

1. 단순 규칙 방식: 정해진 단어, 규칙만으로 텍스트 구분 (문맥 이해 불가)
2. 통계적 학습 방식: 단어의 출현 빈도를 계산하여 분석 (BOW 등)
3. 신경망 학습 방식: 단어와 단어 사이의 연관성 파악 (RNN, Transformer)
4. 최신 AI 모델 방식: 문장 전체의 고차원적 문맥과 의도를 완벽히 이해 (Agent System)

> **[Note]** 우리가 다룰 통계 원문은 결국 사람이 쓴 자연어 텍스트입니다. 컴퓨터가 이 사람의 말을 이해하도록 만드는 기술을 자연어 처리, 영어로는 NLP라고 부르는데, 이 기술이 발전해 온 과정을 네 단계로 정리할 수 있습니다. 첫 번째는 단순 규칙 방식으로, 미리 정해둔 단어나 규칙만으로 텍스트를 구분하는 방식이라 문맥을 전혀 이해하지 못했습니다. 두 번째는 통계적 학습 방식으로, 단어가 얼마나 자주 등장하는지 빈도를 계산해서 분석하는 방식입니다. 세 번째는 신경망 학습 방식으로, RNN이나 트랜스포머 같은 구조를 이용해서 단어와 단어 사이의 연관성을 파악하기 시작했습니다. 그리고 지금 우리가 사용하는 네 번째 단계, 최신 AI 모델 방식에서는 문장 전체의 고차원적인 문맥과 의도까지 거의 완벽하게 이해하는 수준, 즉 에이전트 시스템 수준까지 발전했습니다. 이후 차시에서 배울 형태소 분석이나 키워드 추출 같은 기법들은 사실 이 발전 과정의 두세 번째 단계에 해당하는 통계적 기법이라는 것을 미리 알아두시면 좋습니다.

### 페이지 16. 방대한 글에서 핵심 정보만 뽑아내는 3가지 기술

3대 주요 텍스트마이닝 기술

- 형태소 분석: 문장을 가장 작은 의미 단위(명사, 동사 등)로 쪼개어 분석하는 기술
- 키워드 추출: 문서 안에서 가장 중요하고 자주 등장하는 핵심 단어를 선별하는 기술
- 주제 분류 (토픽 모델링): 여러 문단 속에서 다루고 있는 핵심 주제를 그룹별로 묶어내는 기술

> **[Note]** 방대한 통계 보고서나 설명 자료에서 정말 필요한 핵심 정보만 뽑아내려면 텍스트마이닝이라는 기법이 필요합니다. 대표적으로 세 가지 기술이 있는데요, 첫째는 형태소 분석입니다. 문장을 명사, 동사 같은 가장 작은 의미 단위로 잘게 쪼개서 분석하는 기술입니다. 둘째는 키워드 추출로, 문서 안에서 가장 중요하고 자주 등장하는 핵심 단어를 골라내는 기술입니다. 셋째는 주제 분류, 흔히 토픽 모델링이라고 부르는데, 여러 문단 속에서 다루고 있는 핵심 주제들을 그룹별로 묶어내는 기술입니다. 이 세 가지 기술은 이후 차시에서 실제 파이썬 코드로 직접 구현해 볼 예정이며, 특히 한국어 형태소 분석 도구와 TF-IDF, TextRank라는 구체적인 알고리즘을 사용하게 됩니다.

### 페이지 17. 정밀한 계산 프로그램 방식과 유연한 AI 생성 방식의 결합

Rule-based 규칙 알고리즘과 LLM 생성형 방식의 하이브리드 비교

수치 정확성
- 정밀 계산 프로그램: 100% 완벽함 (오류 없음)
- 생성형 AI 모델: 계산 시 실수할 가능성 있음
- 하이브리드 적용: 계산은 정밀 프로그램이 담당

문장 표현력
- 정밀 계산 프로그램: 정해진 틀만 사용 (단조로움)
- 생성형 AI 모델: 매끄럽고 다양한 표현 가능
- 하이브리드 적용: 문장 작성은 생성형 AI가 담당

핵심 요약: 수치 오차 절대 방지와 읽기 쉬운 보도자료 완성이라는 정확성과 가독성을 모두 확보

> **[Note]** 지금까지 배운 내용을 종합하면, 우리가 만들 시스템은 두 가지 서로 다른 방식의 장점만 골라서 결합한 하이브리드 구조입니다. 수치 정확성 측면에서 보면, 정밀 계산 프로그램은 오류 없이 100% 완벽하지만 생성형 AI 모델은 계산을 시키면 실수할 가능성이 있습니다. 그래서 우리는 계산은 반드시 정밀 프로그램이 담당하도록 설계합니다. 반대로 문장 표현력 측면에서 보면, 정밀 계산 프로그램은 정해진 틀만 반복해서 다소 단조로운 반면, 생성형 AI 모델은 매끄럽고 다양한 표현이 가능합니다. 그래서 문장 작성은 생성형 AI가 담당하도록 역할을 나눕니다. 이렇게 역할을 명확히 분리하면, 숫자 오차는 절대 허용하지 않으면서도 동시에 읽기 쉽고 자연스러운 보도자료를 완성할 수 있게 됩니다. 이 하이브리드 원칙이 바로 이번 과정 전체를 관통하는 가장 핵심적인 설계 철학입니다.

### 페이지 18. AI의 글쓰기 원리와 엉뚱한 답(환각 현상)을 내놓는 이유 (1)

LLM의 동작 원리 및 확률적 생성

글쓰기 원리: 정답을 직접 찾는 것이 아니라, 앞 단어들을 바탕으로 가장 어울리는 다음 단어를 확률적으로 이어붙이는 방식

예시 문장

"철수는 어린 시절 바닷가에서 살았다. 그래서 지금도 철수는 [    ] 소리가 들리면 마음이 편안해진다."

후보 단어: 1) 뱃고동 2) 크락션 3) 철도 4) 비행기

> **[Note]** 이제 AI가 왜 가끔 엉뚱한 답을 내놓는지, 그 근본 원리부터 이해해 보겠습니다. LLM, 즉 거대언어모델의 글쓰기 원리는 우리가 생각하는 것과 다릅니다. AI는 정답을 데이터베이스에서 찾아서 답하는 것이 아니라, 지금까지 나온 단어들을 바탕으로 다음에 올 가장 어울리는 단어를 확률적으로 하나씩 이어 붙이는 방식으로 문장을 만듭니다. 화면의 예시 문장을 보시면, "철수는 어린 시절 바닷가에서 살았다. 그래서 지금도 철수는 [ ] 소리가 들리면 마음이 편안해진다"라는 문장에서 빈칸에 들어갈 단어로 뱃고동, 크락션, 철도, 비행기 네 가지 후보가 있다면, AI는 문맥상 '바닷가'라는 단어와 가장 자연스럽게 어울리는 '뱃고동'을 확률적으로 선택하게 됩니다. 이처럼 AI는 사실관계를 검색하는 것이 아니라 확률적으로 가장 그럴듯한 다음 단어를 예측하는 방식으로 동작한다는 것이 핵심입니다.

### 페이지 19. AI의 글쓰기 원리와 엉뚱한 답(환각 현상)을 내놓는 이유 (2)

환각(Hallucination) 원인 및 대책

- 환각 원인: 사실 여부보다 자연스러운 문장 만들기를 우선시하다 보니 때때로 그럴듯한 거짓말을 만들어 내는 경우 발생
- 해결 방안: AI에게 직접 계산하게 하지 않고, 검증된 숫자를 참고 자료로만 제시하여 문장을 쓰게 함 (에이전트 활용)

> **[Note]** 방금 살펴본 확률적 글쓰기 방식 때문에 생기는 문제가 바로 환각, 영어로 할루시네이션입니다. AI는 사실 여부를 확인하기보다 자연스러운 문장을 만드는 것을 우선시하기 때문에, 때로는 그럴듯하지만 사실과 다른 거짓 내용을 마치 진실인 것처럼 자신 있게 만들어내는 경우가 발생합니다. 예를 들어 존재하지 않는 통계 수치를 마치 실제 발표된 것처럼 자연스럽게 지어낼 수도 있다는 뜻입니다. 그래서 우리는 통계 보도자료처럼 정확성이 생명인 문서를 작성할 때는, AI에게 숫자를 직접 계산하게 하지 않고 이미 검증이 끝난 숫자만 참고 자료로 제시해서 그 안에서만 문장을 쓰도록 통제해야 합니다. 이것이 바로 앞서 배운 3단계 안전장치, 그리고 앞으로 이어질 차시에서 배울 자동 수치 검증 기능이 반드시 필요한 이유입니다.

### 페이지 20. 통계 업무에서 AI에게 시켜야 할 일 (권장)

통계 분석 영역에서 LLM의 역할과 한계점 명시

권장 작업

- 작성된 수치를 바탕으로 읽기 쉬운 보도문 쓰기
- 기사 제목 및 요약문 다각도로 만들어보기
- 딱딱한 개조식 문장을 부드러운 서술체 문장으로 다듬기

> **[Note]** 그렇다면 실제 통계 업무에서 AI에게는 구체적으로 어떤 일을 맡기는 것이 안전하고 효과적일까요? 먼저 이미 정확하게 계산이 끝난 수치를 바탕으로 사람이 읽기 쉬운 보도문을 작성하는 일을 맡길 수 있습니다. 둘째로, 같은 내용이라도 여러 관점에서 기사 제목이나 요약문 후보를 다양하게 만들어보는 작업도 AI가 잘하는 일입니다. 셋째로, 개조식으로 딱딱하게 나열된 문장을 부드럽고 자연스러운 서술체 문장으로 다듬는 작업도 AI에게 맡기기 좋습니다. 이 세 가지의 공통점은 모두 '이미 확정된 사실이나 숫자를 문장으로 표현하는 일'이라는 점입니다. 즉 AI는 표현과 재구성의 영역에서는 탁월하지만, 사실 자체를 판단하거나 계산하는 영역에는 투입하지 않는다는 원칙을 기억해 주세요.

### 페이지 21. 통계 업무에서 AI에게 시키면 안 되는 일 (금지)

통계 분석 영역에서 LLM의 역할과 한계점 명시

금지 작업

- 원본 표 데이터를 주고 직접 증감률이나 비중 계산시키기
- 제시하지 않은 숫자를 스스로 추측해서 쓰게 하기

> **[Note]** 반대로 AI에게 절대로 맡기면 안 되는 일도 명확히 짚고 넘어가겠습니다. 첫째, 원본 표 데이터를 통째로 주고 증감률이나 비중을 AI가 직접 계산하도록 시키는 것은 위험합니다. 계산 과정에서 실수가 생겨도 겉으로는 그럴듯한 문장으로 포장되기 때문에 오류를 알아채기가 매우 어렵습니다. 둘째, 자료에 제시되지 않은 숫자를 AI가 스스로 추측해서 채워 넣도록 하는 것도 절대 금지해야 합니다. 이 두 가지가 바로 앞서 배운 환각 현상이 실제 업무에서 가장 위험하게 나타나는 지점입니다. 그래서 우리는 이 강의 전체에 걸쳐서, 계산이 필요한 모든 부분은 파이썬 프로그램이 직접 수행하고, AI는 그 결과를 전달받아 문장으로만 표현하도록 코드를 설계할 것입니다.

### 페이지 23. 데이터 보안 등급 분류 및 처리 기준

3단계 보안 등급 구조

- 1등급 (비밀, 대외비): 외부 AI 서비스로 전달 절대 금지
- 2등급 (미공개 통계, 공표 전 엠바고): 데이터가 외부에 누설되어 재학습되지 않도록 안전장치가 갖춰진 전용 통로만 이용
- 3등급 (이미 공개된 통계): 일반적인 개방 데이터를 활용해 AI로 가공

참고 기준

- 통계법 기준: 공표 전 통계(미공개 통계)와 공표된 통계 구분
- 보안업무규정: 1급, 2급, 3급 비밀 및 대외비 분류

> **[Note]** 이제부터는 세 번째 주제인 보안 가이드라인으로 넘어가겠습니다. 통계 데이터는 크게 세 등급으로 나눌 수 있습니다. 1등급은 비밀이나 대외비 자료로, 이런 자료는 외부 AI 서비스로 절대 전달해서는 안 됩니다. 2등급은 아직 공식 발표 전인 미공개 통계, 즉 엠바고가 걸려 있는 자료인데, 이런 자료는 외부로 누설되거나 AI 학습에 재활용되지 않도록 안전장치가 갖춰진 전용 통로로만 다뤄야 합니다. 3등급은 이미 일반에 공개된 통계로, 누구나 접근할 수 있는 개방 데이터이기 때문에 AI로 자유롭게 가공해도 괜찮습니다. 이런 구분의 법적 근거는 통계법의 공표 전·후 통계 구분, 그리고 보안업무규정의 1급·2급·3급 비밀 및 대외비 분류에 있습니다. 이번 실습 과정에서는 이미 공개된 3등급 자료만을 다루기 때문에 안심하고 실습을 진행하실 수 있습니다.

### 페이지 24. 생성형 AI 활용 시 정보유출 방지 보안 수칙

핵심 보안 수칙 (Zero Data Retention)

1. 일반 개인용 대화 웹 화면 사용 자제: 입력한 대화 내용이 AI 모델의 재학습에 이용될 위험 존재
2. 전용 개발 연결 통로(API) 활용: 입력 데이터가 서버에 저장되지 않고 즉시 삭제되는 데이터 보존 제로(Zero Data Retention) 정책 적용
3. 데이터 전송 시 암호화 통신 적용: 전송 패킷 탈취 방지를 위한 HTTPS 종단간 암호화 적용

> **[Note]** 통계 데이터 등급과 별개로, 생성형 AI를 실제로 사용할 때 지켜야 할 핵심 보안 수칙 세 가지를 말씀드리겠습니다. 첫째, 일반 개인용 대화형 웹 화면, 그러니까 우리가 흔히 쓰는 챗봇 화면 사용은 업무에서는 자제해야 합니다. 왜냐하면 그런 화면에 입력한 대화 내용이 AI 모델의 재학습에 이용될 위험이 있기 때문입니다. 둘째, 대신 전용 개발 연결 통로, 즉 API를 활용해야 합니다. API를 통해 들어온 데이터는 서버에 저장되지 않고 즉시 삭제되는 '데이터 보존 제로', 영어로 Zero Data Retention 정책이 적용되기 때문에 안전합니다. 셋째, 데이터를 주고받을 때는 반드시 암호화 통신을 적용해서, 전송 중인 패킷이 중간에 탈취되지 않도록 HTTPS 종단간 암호화를 사용해야 합니다. 이후 우리가 실습에서 사용할 Claude API 호출 방식이 바로 이 안전한 방식에 해당합니다.

### 페이지 25. API 연동 시 API Key 보안 관리

안전한 비밀키 관리 (.env 환경변수 활용)

위험한 방식: 코드 내 비밀키 직접 하드코딩 (유출 위험 높음)

```python
api_key = "sk-ant-api03-xxxx..."
```

안전한 방식: 별도 환경설정 파일(.env)에 숨겨두고 불러오기

```
# .env 파일 내용
ANTHROPIC_API_KEY=sk-ant-api03-xxxx...
```

> **[Note]** AI 서비스를 이용하려면 API Key라는 일종의 비밀번호가 필요한데, 이 키를 어떻게 관리하느냐가 매우 중요합니다. 화면에 보이는 첫 번째 예시처럼 소스코드 안에 "api_key = sk-ant-api03-xxxx" 같은 형태로 키 값을 직접 하드코딩해서 적어두는 방식은 매우 위험합니다. 이 코드를 깃허브 같은 곳에 실수로 올리기라도 하면 키가 그대로 외부에 노출되기 때문입니다. 그래서 안전한 방식은, 이 키를 소스코드와는 완전히 분리된 별도의 환경설정 파일, 흔히 점(.)으로 시작하는 ".env"라는 이름의 파일에 숨겨두고, 코드에서는 이 파일을 불러와서 사용하는 것입니다. 우리가 앞으로 실습에서 사용할 ANTHROPIC_API_KEY도 바로 이 .env 파일 방식으로 관리하게 됩니다. 이 원칙은 CLAUDE.md라는 프로젝트 규칙 파일에도 명시해 두고 프로젝트 전체에서 예외 없이 지킬 것입니다.

### 페이지 26. 미공개 통계 처리를 위한 로컬(내 컴퓨터) 내 안전 가공 절차

안전 가공 절차

1. 내부 통계 원본
2. 내 컴퓨터에서 필수 수치만 요약 (개인정보 및 이름 삭제)
3. 최소한의 요약 수치만 AI에 전달
4. 임시 파일 즉시 파기

> **[Note]** 만약 다루는 통계가 아직 공표되지 않은 미공개 자료라면, 어떤 절차로 안전하게 처리해야 할까요? 네 단계로 정리할 수 있습니다. 첫째, 내부 통계 원본 자료를 확보합니다. 둘째, 이 원본을 통째로 AI에 보내는 것이 아니라, 내 컴퓨터 안에서 먼저 보도자료 작성에 꼭 필요한 최소한의 수치만 요약하고, 이 과정에서 개인정보나 담당자 이름 같은 민감한 정보는 먼저 삭제합니다. 셋째, 이렇게 정제된 최소한의 요약 수치만 AI에게 전달합니다. 넷째, 작업이 모두 끝나고 나면 이 과정에서 만들어진 임시 파일들은 즉시 파기합니다. 이렇게 하면 원본 데이터 전체가 외부로 나갈 위험을 원천적으로 차단하면서도, AI의 도움은 그대로 받을 수 있습니다.

### 페이지 27. 개인정보 자동 가리기(마스킹) 프로그램

파이썬 정규표현식 마스킹 코드

```python
import re

def mask_sensitive_info(text: str) -> str:
    # 주민등록번호 별표 가리기
    text = re.sub(r'\d{6}-[1-4]\d{6}', '******-*******', text)
    # 전화번호 별표 가리기
    text = re.sub(r'01[016789]-\d{3,4}-\d{4}', '010-****-****', text)
    return text
```

> **[Note]** 방금 설명한 절차 중 '개인정보 삭제' 부분을 실제 코드로 어떻게 자동화하는지 보여드리겠습니다. 화면의 파이썬 코드는 정규표현식을 이용해서 텍스트 안의 개인정보를 자동으로 가려주는 함수입니다. 첫 번째 정규식은 주민등록번호 형태의 패턴을 찾아서 별표로 가려주고, 두 번째 정규식은 010으로 시작하는 휴대전화번호 패턴을 찾아서 마찬가지로 별표로 가려줍니다. 여기서 중요한 포인트는, 이런 개인정보 삭제를 AI에게 프롬프트로 "개인정보는 지워줘"라고 부탁하는 방식이 아니라, 코드로 확실하게 전처리해서 애초에 AI에게 전달되는 텍스트 안에 개인정보가 남아있지 않도록 만든다는 것입니다. 이 함수는 실제로 다음 차시에서 배울 전체 데이터 정제 파이프라인 안에 그대로 포함되어서, 모든 원문 텍스트에 항상 자동으로 적용됩니다.

### 페이지 28. 보도자료 작성 전 꼭 확인해야 할 5가지 보안 점검표

보안 점검표 (Checklist)

1. AI 비밀키가 코드 안에 직접 노출되어 있지 않은가
2. 입력 데이터가 외부에 남지 않는 전용 API를 사용하고 있는가
3. 미공개 통계 데이터를 개인 대화형 웹창에 직접 넣지 않았는가
4. 개인정보나 민감한 정보가 별표로 잘 가려졌는가
5. 완성된 글의 숫자를 작성자가 직접 최종 확인하였는가

> **[Note]** 마지막으로, 통계 보도자료를 실제로 배포하기 전에 반드시 확인해야 할 다섯 가지 보안 점검표로 이번 시간을 마무리하겠습니다. 첫째, AI 비밀키가 코드 안에 직접 노출되어 있지 않은지 확인합니다. 둘째, 입력 데이터가 외부에 남지 않는 전용 API를 사용하고 있는지 확인합니다. 셋째, 미공개 통계 데이터를 개인용 대화형 웹창에 직접 입력하지 않았는지 확인합니다. 넷째, 개인정보나 민감한 정보가 제대로 별표로 가려졌는지 확인합니다. 다섯째, 그리고 가장 중요한 것으로, 완성된 글에 들어간 모든 숫자를 작성자가 사람의 눈으로 직접 최종 확인했는지 점검합니다. 이 다섯 가지 항목은 앞으로 여러 차시에 걸쳐 실습을 진행하면서 계속 다시 언급될 것이고, 마지막 차시에서 전체 시스템을 완성했을 때 다시 한번 최종 점검하게 됩니다. 그럼 이제 본격적으로 다음 차시부터 데이터를 다루는 실습을 시작해 보겠습니다.

### 페이지 29. 정리하기

1. AI와 프로그램이 역할을 나누는 하이브리드 자동화 구조
  - 수치 계산은 정밀한 컴퓨터 프로그램이 전담하고, 문장 작성은 생성형 AI가 담당하는 5단계 파이프라인과 3단계 안전장치의 원리를 배웠습니다.
  - 이 역할 분담 원칙은 앞으로 이어지는 모든 차시에서 실제 코드로 하나씩 구현해 나갈 이번 과정 전체의 핵심 설계 철학입니다.
2. AI·머신러닝·딥러닝·자연어 처리 개념의 이해
  - 인공지능, 머신러닝, 딥러닝, 생성형 AI가 서로 포함 관계에 있다는 것과, LLM이 확률적으로 다음 단어를 예측하는 방식으로 글을 쓰기 때문에 환각(hallucination) 현상이 생길 수 있다는 것을 배웠습니다.
  - 이 때문에 AI에게는 표현과 재구성만 맡기고, 사실 판단이나 수치 계산은 맡기지 않는다는 원칙이 중요하다는 것을 확인했습니다.
3. 통계 데이터를 다루는 내부 보안 가이드라인
  - 통계 데이터의 보안 등급 구분, API 키를 .env 파일로 안전하게 관리하는 방법, 개인정보를 코드로 자동 마스킹하는 절차를 배웠습니다.
  - 보도자료 배포 전 다섯 가지 보안 점검표는 앞으로 실습을 진행하는 내내, 그리고 전체 시스템이 완성되었을 때 다시 한번 확인하게 될 기준입니다.
