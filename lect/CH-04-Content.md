### 페이지 07. 좋은 프롬프트의 조건

프롬프트 설계 4대 원칙

- 역할 부여: AI에게 어떤 입장에서 답해야 하는지 명확히 지정 (예: 통계청 보도자료 작성 담당자)
- 맥락 제공: 참고할 데이터(계산지표, 핵심키워드, 주요문장)를 구체적으로 함께 제시
- 출력 형식 지정: 결과를 원하는 형태(3줄 요약, JSON 등)로 명확히 요청
- 제약 조건 명시: 제공된 숫자 외에는 새로운 수치를 만들어내지 말 것을 명확히 지시

> **[Note]** 프롬프트는 AI에게 전달하는 업무 지시서와 같습니다. 지시서가 모호하면 결과물도 모호해지듯이, 프롬프트도 원하는 품질의 요약문을 얻기 위해서 고려할 것이 몇가지 입습니다.  첫째는 역할 부여로, AI에게 통계청 보도자료 작성 담당자처럼 구체적인 입장을 지정해 줍니다. 둘째는 맥락 제공으로, 계산지표나 핵심키워드, 주요문장 같은 참고 데이터를 구체적으로 함께 제시합니다. 셋째는 출력 형식 지정으로, 3줄 요약이나 JSON처럼 원하는 결과 형태를 명확히 요청합니다. 넷째는 제약 조건 명시로, 제공된 숫자 외에는 새로운 수치를 절대 만들어내지 말라고 분명히 지시하는 것입니다. 이 네 가지를 갖추지 않으면 AI가 엉뚱한 방향으로 답을 만들어낼 가능성이 커집니다.

### 페이지 08. 통계 보도자료 요약 프롬프트 설계 실습

시스템 프롬프트와 사용자 프롬프트 예시

```
[시스템 프롬프트]
당신은 통계청 보도자료 작성 담당자입니다. 제공된 계산지표와 핵심 문장만을 근거로
사용하여 요약문을 작성하십시오. 제공되지 않은 숫자는 절대로 만들어내지 마십시오.

[사용자 프롬프트]
다음 자료를 참고하여 3줄 요약과 제목 후보 3개를 작성해 주세요.
계산지표: 총거래액 201,250억 원, 전월대비 1.5% 증가, 전년동월대비 8.7% 증가
핵심키워드: 온라인쇼핑, 거래액, 역대, 최대
주요문장: "이는 역대 1월 기준 최대치를 기록한 것이다."
```

> **[Note]** 방금 배운 네 가지 원칙을 실제 프롬프트로 옮기면 이런 모습이 됩니다. 시스템 프롬프트에서는 AI의 역할과 반드시 지켜야 할 규칙, 즉 "제공된 숫자 외에는 절대 만들어내지 말 것"을 먼저 설정합니다. 그리고 사용자 프롬프트에서는 실제 계산지표, 핵심키워드, 주요문장 같은 참고 데이터와 함께 원하는 작업, 즉 3줄 요약과 제목 후보 3개를 만들어달라고 구체적으로 전달합니다. 이렇게 역할 설정과 실제 데이터를 시스템 프롬프트와 사용자 프롬프트로 나누어 분리하면, 프롬프트를 관리하기도 쉬워지고 AI가 규칙을 훨씬 안정적으로 지키게 됩니다.

### 페이지 09. Claude API 호출 기본 구조

anthropic 파이썬 SDK 기본 사용법

```python
import anthropic

client = anthropic.Anthropic()  # .env의 ANTHROPIC_API_KEY 자동 로드
MODEL_NAME = "claude-sonnet-4-5"  # 실습 시점에 console.anthropic.com에서 최신 모델 ID를 확인하여 교체

message = client.messages.create(
    model=MODEL_NAME,
    max_tokens=500,
    system="당신은 통계청 보도자료 작성 담당자입니다...",
    messages=[
        {"role": "user", "content": "다음 자료를 참고하여 3줄 요약을 작성해 주세요..."}
    ]
)
print(message.content[0].text)
```

> **[Note]** 이제 이 프롬프트를 실제 Claude API로 호출하는 파이썬 코드를 보여드리겠습니다. client.messages.create 함수에 사용할 모델, 최대 생성 길이인 max_tokens, 시스템 프롬프트, 사용자 메시지를 담아 요청하면 AI가 생성한 응답 텍스트를 돌려받습니다. 여기서 한 가지 설계상 중요한 포인트가 있습니다. 모델 이름을 "claude-sonnet-4-5"라고 코드 여기저기에 반복해서 적지 않고, MODEL_NAME이라는 상수 하나로 정의해 둔다는 점입니다. 이렇게 해두면 이후 API를 호출하는 여러 차시의 모든 코드가 이 상수 하나를 공유하게 되고, 나중에 더 새로운 모델이 나와서 교체해야 할 때도 이 한 줄만 고치면 전체 시스템에 반영됩니다. 실습을 진행하실 때는 콘솔에서 현재 사용 가능한 최신 모델 ID를 확인해서 이 상수에 넣어주시면 됩니다.

### 페이지 11. Python 코드, 요약 프롬프트 함수로 구현하기

표준 데이터를 프롬프트 문자열로 변환하는 함수

```python
def build_summary_prompt(data: dict) -> str:
    지표 = data["계산지표"]
    키워드 = ", ".join(data["NLP분석결과"]["핵심키워드"])
    주요문장 = data["NLP분석결과"]["주요문장"][0]

    return f"""다음 자료를 참고하여 3줄 요약과 제목 후보 3개를 작성해 주세요.
계산지표: 총거래액 {지표['총거래액']}억 원, 전월대비 {지표['전월대비증감률']}% 증가,
전년동월대비 {지표['전년동월대비증감률']}% 증가
핵심키워드: {키워드}
주요문장: "{주요문장}\""""
```

> **[Note]** 지금까지는 프롬프트를 손으로 직접 써봤다면, 이제는 이 프롬프트를 자동으로 만들어내는 함수를 작성해 보겠습니다. build_summary_prompt 함수는 이전에 완성한 표준 데이터 구조를 통째로 입력받아서, 그 안의 계산지표와 핵심키워드, 주요문장을 꺼내 프롬프트 문자열 안에 자동으로 채워 넣습니다. 이렇게 함수로 만들어두면, 어떤 통계자료가 들어오더라도 매번 손으로 프롬프트를 새로 쓸 필요 없이 항상 동일한 형식으로 자동 생성할 수 있습니다.

### 페이지 13. Python 코드, API 호출부터 결과 파싱까지

전체 요약 생성 함수

```python
import json
import re

def parse_json_response(response_text: str):
    """모델 응답에서 코드펜스(```json ... ```)나 부연 설명이 섞여 있어도 JSON 객체({})나 배열([])만 추출해 파싱한다."""
    match = re.search(r"(\{.*\}|\[.*\])", response_text, re.DOTALL)
    json_text = match.group(0) if match else response_text
    return json.loads(json_text)

def generate_summary(data: dict) -> dict:
    prompt = build_summary_prompt(data)
    message = client.messages.create(
        model=MODEL_NAME,
        max_tokens=500,
        system="당신은 통계청 보도자료 작성 담당자입니다. 제공된 숫자만 사용하고 "
               "반드시 JSON 형식으로만 답하십시오.",
        messages=[{"role": "user", "content": prompt}]
    )
    return parse_json_response(message.content[0].text)

summary_result = generate_summary(data)
print(summary_result)
```

> **[Note]** 프롬프트 생성부터 API 호출, JSON 파싱까지 전 과정을 하나의 generate_summary 함수로 묶었습니다. 표준 데이터 하나만 입력하면 3줄 요약과 제목 후보가 담긴 딕셔너리 결과를 곧바로 얻을 수 있습니다. 여기서 parse_json_response라는 함수를 눈여겨봐 주세요. 시스템 프롬프트로 "JSON 형식으로만 답하라"고 아무리 강하게 지시해도, 실제로 모델이 다른 표시나 설명을 앞뒤에 덧붙이는 경우가 실제로 많습니다. 그래서 이 함수는 응답 문자열 전체를 그대로 파싱하지 않고, 정규식으로 중괄호나 대괄호로 감싸인 JSON 부분만 정확히 찾아내서 파싱합니다. 이렇게 방어적으로 파싱하도록 만들어두면, 응답에 부연 설명이 섞여 있어도 오류 없이 안전하게 처리할 수 있습니다. 이 함수는 이후 헤드라인 생성, AI 감수 결과 파싱에서도 똑같이 재사용됩니다. 그리고 한 가지 더 알아두실 점은, temperature 값이 0보다 큰 LLM 호출은 같은 입력을 다시 넣어도 매번 문장이 다르게 나올 수 있다는 것입니다. 실습 중에 화면에 나온 예시와 표현이 다르게 나온다고 해서 잘못된 것이 아니라, 숫자와 사실관계가 원본과 일치하는지만 확인하면 충분합니다. 실제로 이 generate_summary 함수는 전체 파이프라인의 계산 단계 다음에 호출되어, 그 결과가 이후 제목·부제·리드문 생성 단계에 참고 자료로 전달됩니다. 다만 이 결과가 최종 숫자나 사실을 결정하지는 않으며, 사실 확정은 LLM이 아니라 파이썬 함수의 계산 결과가 담당한다는 원칙은 변하지 않습니다.

### 페이지 14. Temperature 등 생성 파라미터 이해하기

주요 생성 파라미터

- temperature: 값이 낮을수록 일관되고 보수적인 문장, 높을수록 다양하고 창의적인 문장 (보도자료는 0.2~0.4 권장)
- max_tokens: AI가 생성할 수 있는 최대 글자(토큰) 수 제한
- top_p: 후보 단어 선택 범위를 조절하는 값 (temperature와 유사한 역할)

> **[Note]** 방금 언급한 temperature를 포함해서, AI의 생성 방식을 조절하는 주요 파라미터 세 가지를 정리하겠습니다. temperature는 값이 낮을수록 일관되고 보수적인 문장이 나오고, 값이 높을수록 다양하고 창의적인 문장이 나옵니다. 보도자료처럼 정확성과 일관성이 중요한 문서에서는 0.2에서 0.4 사이의 낮은 값을 권장합니다. max_tokens는 AI가 생성할 수 있는 최대 글자, 정확히는 토큰 수를 제한하는 값입니다. top_p는 temperature와 비슷하게 후보 단어의 선택 범위를 조절하는 역할을 합니다. 정리하면, 값을 너무 높이면 표현은 다채로워지지만 사실과 다른 과장된 표현이 나올 위험도 함께 커지므로, 보도자료 작성에서는 항상 보수적인 설정을 기본으로 사용하면서 조절하는 것이 좋습니다.

### 페이지 17. 요약 결과 검토 체크리스트

검토해야 할 4가지 항목

1. 원본에 없는 새로운 숫자가 생성되지는 않았는가
2. %와 %p 표현이 정확히 구분되어 사용되었는가
3. 과장되거나 단정적인 표현("압도적", "폭발적")이 사용되지는 않았는가
4. 제목 후보가 핵심내용을 왜곡 없이 담고 있는가

> **[Note]** AI가 아무리 잘 만든 문장이라도 반드시 사람이 검토하는 단계를 거쳐야 합니다. 검토할 때 확인해야 할 네 가지는 이렇습니다. 첫째, 원본에 없는 새로운 숫자가 생성되지는 않았는지. 둘째, %와 %p 표현이 정확히 구분되어 사용되었는지. 셋째, "압도적", "폭발적" 같은 과장되거나 단정적인 표현이 쓰이지는 않았는지. 넷째, 제목 후보가 핵심내용을 왜곡 없이 담고 있는지입니다. 특히 수치와 관련된 표현은 사소한 오류 하나만으로도 보도자료 전체의 신뢰도가 크게 흔들릴 수 있으므로, 이 체크리스트를 꼼꼼히 적용하는 것이 중요합니다.

### 페이지 18. Python 코드, 원본 수치와 생성 문장 자동 대조

수치 일치 여부를 자동 검증하는 함수

```python
import re

def _collect_valid_numbers(data: dict) -> set:
    """계산지표(단일 딕셔너리)와 품목별지표(딕셔너리 리스트) 양쪽 스키마에서 숫자 값을 모두 모은다."""
    valid = set()
    for v in data.get("계산지표", {}).values():
        if isinstance(v, (int, float)):
            valid.add(str(v))
    for row in data.get("품목별지표", []):
        for v in row.values():
            if isinstance(v, (int, float)):
                valid.add(str(v))
    return valid

def _is_low_risk_number(token: str) -> bool:
    """연도(4자리)·순위·개월 수 등 1~2자리 숫자는 문맥상 자연스럽게 등장하므로 대조 대상에서 제외한다."""
    if "." in token:
        return False  # 소수(증감률 등)는 항상 정밀 대조
    if len(token) == 4 and token.isdigit() and 1900 <= int(token) <= 2100:
        return True
    return len(token) <= 2

def find_unverified_numbers(text: str, data: dict) -> list:
    """text에 등장하는 숫자 중 원본 데이터로 근거를 확인할 수 없는 것만 골라 반환한다."""
    valid_numbers = _collect_valid_numbers(data)
    unmatched = []
    for raw in re.findall(r'\d[\d,]*\.?\d*', text):
        cleaned = raw.replace(",", "")
        if _is_low_risk_number(cleaned):
            continue
        if cleaned not in valid_numbers:
            unmatched.append(raw)
    return unmatched

def verify_numbers(summary_text: str, source_data: dict) -> bool:
    return len(find_unverified_numbers(summary_text, source_data)) == 0

is_valid = verify_numbers(summary_result["삼줄요약"][0], data)
```

> **[Note]** 이제 방금 배운 검토 체크리스트 중에서 가장 중요한 첫 번째 항목, 즉 숫자 검증을 실제 코드로 자동화해 보겠습니다. verify_numbers 함수는 요약문 안에 등장하는 모든 숫자를 정규표현식으로 추출한 뒤, 원본 계산지표나 품목별지표에 실제로 존재하는 숫자인지 하나하나 자동으로 대조합니다. 이 검증을 통과하지 못하면 AI가 없는 숫자를 만들어냈다는 뜻이므로, 사람이 다시 검토해야 한다는 신호로 활용합니다. 코드에 대한 자세한 주석은 이곳에서 다루지 않겠습니다. LLM 을 사용해서 직접 물어보시면 AI 가 잘 대답해 줄 것입니다.

### 페이지 19. 잘못된 요약 사례와 수정 예시

환각(Hallucination) 사례와 대응

- 잘못된 사례: "역대 최대 실적을 압도적으로 경신하며 사상 최고의 성장세를 보였다" (원본에 없는 과장 표현 추가)
- 수정 방향: "역대 1월 기준 최대치를 기록하였다" (제공된 사실 그대로만 서술)
- 대응 방법: 프롬프트에 "객관적 사실만 서술하고 수식어를 남용하지 말 것"을 명시적으로 추가

> **[Note]** 실제로 AI가 어떤 식으로 과장을 하는지 잘못된 사례로 살펴보겠습니다. "역대 최대 실적을 압도적으로 경신하며 사상 최고의 성장세를 보였다"라는 문장은 원본에 없는 "압도적", "사상 최고" 같은 과장 표현이 추가된 사례입니다. 이걸 "역대 1월 기준 최대치를 기록하였다"처럼 제공된 사실 그대로만 담담하게 서술하도록 고쳐야 합니다. AI는 자연스러운 문장을 만들기 위해 종종 이렇게 사실보다 과장된 표현을 덧붙이는 경향이 있습니다. 이런 경우를 발견하면 그 자리에서 결과를 직접 고치는 것과 동시에, 다음번 프롬프트에는 "객관적 사실만 서술하고 수식어를 남용하지 말 것"이라는 규칙을 명시적으로 추가해서 같은 문제가 반복되지 않도록 관리해야 합니다.

### 페이지 20. 검증을 마친 요약 결과를 표준 데이터에 저장

표준 JSON 확장, 요약결과 필드 추가

```json
{
  "NLP분석결과": { "핵심키워드": ["온라인쇼핑", "거래액", "역대", "최대"] },
  "요약결과": {
    "삼줄요약": [

      "이는 전월 대비 1.5%, 전년동월대비 8.7% 증가한 수치이다.",
      "역대 1월 기준 최대치를 달성하였다."
    ],
    "제목후보": [
      "1월 온라인쇼핑 거래액, 역대 최대 기록",
      "온라인쇼핑 거래액 8.7% 증가, 1월 최대치 경신",
      "1월 온라인쇼핑 동향, 거래액 역대 최고 수준"
    ]
  }

```

> **[Note]** 검증까지 마친 3줄 요약과 제목 후보를 "요약결과"라는 새로운 필드로 표준 데이터에 저장합니다. 화면에 보시는 것처럼 3줄요약과 제목후보가 나란히 담기게 됩니다. 이 결과 중 제목후보는 이후 제목·부제·리드문 생성 단계에서 참고용 아이디어로 전달되어, AI가 표현을 구상할 때 힌트로 활용됩니다. 다만 최종 제목이나 리드문에 들어가는 숫자와 사실관계는 이 요약결과가 아니라 계산되고 검증된 수치를 근거로 결정된다는 점을 다시 한번 기억해 주시기 바랍니다.
이 강의 전체와 관련해 한 가지 생각을 나누고 싶습니다. 앞으로 AI Agent가 더 정교해지면, 오늘 익힌 과정 자체가 필요 없어지는 날이 올 수도 있습니다. "보도자료 만들어줘"라는 한마디만으로 지금까지의 모든 과정을 환각 없이 처리해 주는 시대가 올 수 있다는 뜻입니다. 하지만 그런 시대가 오더라도 원리는 같습니다. 사람이 명령을 내리면 AI Agent가 이를 작은 단계로 쪼개어 순차적으로 처리하며 오류를 최소화한다는 점은 변하지 않기 때문입니다. 오늘 직접 밟아본 과정을 나중에는 AI Agent가 대신 수행하게 될 뿐이니, 이 과정을 불필요한 수고로 여기기보다 앞으로 당연해질 흐름을 한발 먼저 경험해 보는 것으로 받아들이면 좋겠습니다. 컴퓨터와 계산기가 모든 계산을 대신하지만 여전히 우리는 덧셈, 뺄셈, 곱셈, 나눗셈을 배우고 연습하듯, 원리를 아는 것이 중요하기 때문입니다. 그래서 이 과정에서는 최근 주목받는 하네스, MCP 같은 기술의 사용을 최소화하고, API만으로 AI Agent를 직접 만들어보고 있습니다.

### 페이지 21. 정리하기

1. 좋은 프롬프트의 네 가지 조건
  - 역할 부여, 맥락 제공, 출력 형식 지정, 제약 조건 명시라는 네 가지 요소를 프롬프트에 담아 설계하는 방법을 배웠습니다.
  - 이 네 가지를 갖추지 않으면 AI가 엉뚱한 방향으로 답을 만들어낼 가능성이 커진다는 것을 확인했습니다.
2. Claude API를 이용한 요약문 생성
  - Claude API를 호출해 통계자료를 3줄 요약과 제목 후보로 JSON 형식으로 생성하는 방법과, 응답에 부연 설명이 섞여도 안전하게 파싱하는 방어적 파싱 요령을 배웠습니다.
  - temperature 같은 생성 파라미터를 조절해 보도자료에 적합한 보수적이고 일관된 문장을 얻는 방법도 함께 익혔습니다.
3. 생성 결과의 자동 검증
  - 생성된 문장 속 숫자를 원본 데이터와 자동으로 대조해서, AI가 없는 숫자를 지어내는 환각 현상이 있었는지 검증하는 방법을 배웠습니다.
