### 페이지 06. 통계자료의 두 얼굴, 정형 데이터와 비정형 데이터

데이터 유형 구분의 출발점

- 정형 데이터: 행과 열로 이루어진 표 형태의 데이터 (엑셀, CSV, 데이터베이스 등)
- 비정형 데이터: 정해진 틀이 없는 자유 형식의 데이터 (보고서 문서, 뉴스 기사, 이미지 등)
- AI 기반 보도자료 자동화 시스템은 이 두 가지 데이터를 모두 입력으로 받아 처리해야 함

> **[Note]** 통계 보도자료를 자동으로 작성하려면 가장 먼저 다뤄야 할 원본 자료가 어떤 형태인지 파악해야 합니다. 통계표처럼 행과 열로 깔끔하게 정리된 자료를 정형 데이터라고 부르고, 담당자가 작성한 설명 보고서나 참고 문서처럼 형식이 정해져 있지 않은 자료를 비정형 데이터라고 부릅니다. 실제 현업에서는 이 두 가지가 항상 함께 존재합니다. 예를 들어 이번 달 온라인쇼핑 거래액이라는 숫자는 엑셀 표(정형)로 오지만, "이번 달은 프로모션 영향으로 거래액이 늘었다"는 배경 설명은 담당자가 쓴 메모(비정형)로 옵니다. 우리가 만들 자동화 시스템은 이 두 가지 형태를 모두 입력으로 받아서, 각각에 맞는 방식으로 처리한 뒤 하나의 결과물로 합쳐내야 합니다. 오늘은 먼저 이 두 데이터가 각각 어떤 특징을 가지는지 하나씩 짚어보겠습니다.

### 페이지 07. 정형 데이터(Structured Data)의 특징과 예시

정형 데이터의 핵심 속성

- 명확한 스키마(항목명, 데이터 타입)가 미리 정의되어 있음
- 행(레코드)과 열(필드) 구조로 정렬되어 있어 연산과 검색이 용이
- 예시: 통계청 KOSIS 통계표, 엑셀 원자료(xlsx), 데이터베이스 테이블(CSV)
- 장점: 프로그램이 즉시 계산, 집계, 정렬 처리 가능

> **[Note]** 정형 데이터의 첫 번째 특징은 스키마, 즉 어떤 항목이 어떤 이름과 형식으로 존재하는지가 미리 정해져 있다는 점입니다. 그리고 행과 열이라는 표 구조로 가지런히 정렬되어 있어서, 컴퓨터가 특정 항목을 찾거나 계산하기가 아주 쉽습니다. 대표적인 예시로는 통계청 KOSIS에서 내려받는 통계표, 담당자가 정리한 엑셀 원자료(xlsx), 그리고 데이터베이스의 CSV 테이블 등이 있습니다. 이런 정형 데이터의 가장 큰 장점은, 프로그램이 별도의 해석 과정 없이 곧바로 계산하고, 집계하고, 정렬할 수 있다는 것입니다. 예를 들어 엑셀 파일의 "거래액" 열을 그대로 pandas 같은 도구로 읽어오면, 별다른 가공 없이 바로 합계나 평균, 순위를 구할 수 있습니다. 우리가 5차시에서 배울 증감률 계산도 결국 이런 정형 데이터를 전제로 합니다.

### 페이지 08. 비정형 데이터(Unstructured Data)의 특징과 예시

비정형 데이터의 핵심 속성

- 고정된 항목이나 구조 없이 자유로운 형식으로 존재
- 예시: 보도자료 원본 PDF, 설명 보고서 문서, 담당자 작성 메모, 뉴스 기사 텍스트
- 문자, 문장 형태이므로 곧바로 수치 연산에 사용할 수 없음
- AI(자연어 처리) 기술을 통해 의미 있는 정보로 변환하는 과정이 반드시 필요

> **[Note]** 반대로 비정형 데이터는 고정된 항목이나 구조가 전혀 없이, 사람이 자유롭게 쓴 형식 그대로 존재하는 자료입니다. 보도자료 원본 PDF, 담당자가 작성한 설명 메모, 뉴스 기사 텍스트 등이 대표적인 예시입니다. 이런 자료는 사람이 읽기에는 전혀 문제가 없지만, 컴퓨터 입장에서는 어디에 어떤 숫자가 있는지, 어떤 문장이 중요한지 스스로 알아낼 방법이 없습니다. 즉 비정형 데이터는 문자와 문장의 나열일 뿐이라, 곧바로 수치 연산에 사용할 수가 없다는 뜻입니다. 그래서 비정형 데이터 안에서 핵심 수치나 키워드, 중요한 문장을 뽑아내는 작업이 반드시 필요한데, 이것이 바로 3차시에서 배울 자연어 처리, 즉 텍스트마이닝 기술입니다. 오늘은 이 비정형 데이터를 일단 정제하고 표준화하는 방법까지만 다루고, 실제 분석은 3차시에서 이어서 진행합니다.

### 페이지 09. 반정형 데이터(Semi-structured Data)와 활용 가치

정형과 비정형의 중간 형태

- 반정형 데이터: 완전한 표 구조는 아니지만 태그나 구분자로 일정한 규칙을 가진 데이터
- 대표 형식: JSON, XML, HTML 표, 로그 파일
- 특징: 항목 이름은 있지만 행과 열처럼 고정된 크기의 표는 아님
- 보도자료 자동화 파이프라인에서는 정형 데이터를 반정형(JSON) 형태로 변환하여 모듈 간에 주고받는 것이 표준

> **[Note]** 정형 데이터와 비정형 데이터 사이에는 반정형 데이터라는 중간 형태가 있습니다. 완전한 표 구조는 아니지만, JSON이나 XML처럼 태그나 구분자로 일정한 규칙을 가지고 있는 데이터입니다. 항목마다 이름표는 붙어 있지만, 엑셀처럼 행과 열의 개수가 고정된 표는 아니라는 것이 특징입니다. 왜 이게 중요하냐면, 우리가 1차시에서 이미 살펴본 JSON 형식이 바로 이 반정형 데이터에 해당하기 때문입니다. 우리가 만들 보도자료 자동화 파이프라인에서는, 원본이 정형 데이터든 비정형 데이터든 상관없이, 각 모듈을 거칠 때마다 이 JSON이라는 반정형 구조로 통일해서 데이터를 주고받는 것을 표준으로 삼습니다. 즉 오늘 우리가 최종적으로 만들 결과물도 결국 이 JSON 형태의 반정형 데이터가 됩니다.

### 페이지 10. 통계 보도자료 작성 관점에서 본 데이터 유형별 활용 전략

데이터 유형별 처리 전략 비교

- 정형 데이터: 수치 계산 프로그램이 직접 집계, 연산 수행
- 비정형 데이터: 텍스트마이닝으로 핵심 문장, 키워드 추출 후 정제
- 반정형 데이터(JSON): 모듈 간 표준 전달 형식으로 사용

결론: 세 가지 데이터 유형을 각각의 특성에 맞게 처리한 뒤, 최종적으로 표준화된 하나의 데이터 구조로 통합해야 함

> **[Note]** 지금까지 배운 세 가지 데이터 유형을 정리하면서, 각각을 어떻게 처리할지 전략을 세워보겠습니다. 정형 데이터는 수치 계산 프로그램이 직접 집계하고 연산합니다. 예를 들어 엑셀의 거래액 데이터는 5차시에서 배울 pandas 계산 코드가 처리합니다. 비정형 데이터는 텍스트마이닝 기법으로 핵심 문장과 키워드를 먼저 추출한 뒤 정제합니다. 그리고 반정형 데이터인 JSON은 이렇게 처리된 결과들을 모듈 간에 표준적으로 주고받는 전달 형식으로 사용합니다. 결론적으로, 우리는 세 가지 데이터 유형을 각각의 특성에 맞는 방식으로 먼저 처리한 뒤, 최종적으로는 반드시 하나의 표준화된 JSON 구조로 통합해야 합니다. 이 통합된 구조가 있어야만 다음 단계인 AI 분석과 문장 생성 모듈이 일관되게 동작할 수 있습니다.

### 페이지 12. 데이터 항목 정의가 왜 중요한가

항목 정의 부재 시 발생하는 문제

- 같은 지표를 부서마다 다른 이름으로 불러 데이터 통합 시 혼선 발생 (예: 거래액과 매출액)
- 단위 표기가 통일되지 않아 AI가 문장을 작성할 때 오류 발생 가능 (예: 억 원과 백만 원)
- 항목 정의가 없으면 AI에게 어떤 데이터를 참고 자료로 줄지 결정하기 어려움

> **[Note]** 이제 두 번째 소주제로 넘어가서, 데이터를 AI에게 전달하기 전에 각 항목이 무엇을 의미하는지 명확히 정의해 두는 작업의 중요성을 살펴보겠습니다. 만약 항목명과 단위가 부서나 자료마다 제각각이라면 어떤 문제가 생길까요? 예를 들어 어떤 부서는 "거래액"이라 부르고 다른 부서는 같은 개념을 "매출액"이라고 부른다면, 프로그램이 자동으로 이 둘을 통합할 때 서로 다른 지표로 착각할 수 있습니다. 또한 어떤 자료는 "억 원" 단위로, 어떤 자료는 "백만 원" 단위로 쓰여 있다면, 단위를 맞추지 않고 그대로 계산했을 때 백 배 차이가 나는 심각한 오류가 발생할 수도 있습니다. 그리고 무엇보다, 항목 정의가 명확하지 않으면 AI에게 어떤 데이터를 참고 자료로 줘야 할지조차 결정하기 어려워집니다. 그래서 본격적으로 데이터를 다루기 전에, 항목의 이름과 의미, 단위를 미리 명확하게 약속해 두는 것이 이번 소주제의 목표입니다.

### 페이지 13. 필수 항목과 선택 항목 구분하기

항목 분류 기준

- 필수 항목: 보도자료 리드문과 제목 작성에 반드시 필요한 핵심 지표 (예: 총거래액, 증감률)
- 선택 항목: 본문 부연 설명에 활용되는 부가 지표 (예: 세부 품목별 비중, 지역별 순위)
- 참고 항목: 문맥 이해를 돕는 배경 정보 (예: 통계 작성 기관, 조사 대상 기간)

> **[Note]** 모든 데이터 항목이 다 똑같이 중요한 것은 아닙니다. 만약 모든 데이터를 동일한 중요도로 취급한다면, AI가 정작 강조해야 할 핵심을 놓치고 부차적인 내용을 앞세워 버릴 위험이 있습니다. 그래서 우리는 항목을 세 등급으로 나눕니다. 첫째, 필수 항목은 보도자료의 제목과 리드문에 반드시 들어가야 하는 핵심 지표로, 총거래액이나 증감률 같은 것이 여기에 해당합니다. 둘째, 선택 항목은 본문에서 부연 설명할 때 활용하는 부가 지표로, 세부 품목별 비중이나 지역별 순위 같은 것입니다. 셋째, 참고 항목은 문맥을 이해하는 데 도움을 주는 배경 정보로, 통계를 작성한 기관이나 조사 대상 기간 같은 것입니다. 이렇게 세 등급으로 미리 나눠두면, 이후 7차시에서 핵심지표를 자동으로 선정하는 로직을 만들 때 이 분류 기준을 그대로 코드에 반영하게 됩니다.

### 페이지 14. 데이터 딕셔너리(사전) 설계 방법

데이터 딕셔너리 구성 요소

- 항목명(한글, 영문): 데이터를 식별하는 고유한 이름
- 데이터 타입: 숫자, 문자열, 날짜 등 형식 지정
- 단위: 원, 억 원, %, %p 등 명시
- 정의 설명: 해당 항목이 의미하는 바를 한 문장으로 기술

예시

```json
{
  "항목명": "전월대비증감률",
  "타입": "숫자(소수점 1자리)",
  "단위": "%",
  "정의": "전월 대비 이번 달 수치의 증감 비율"
}
```

> **[Note]** 방금 분류한 필수·선택·참고 항목들을 실제로 문서화하는 방법이 바로 데이터 딕셔너리, 우리말로 하면 데이터 사전입니다. 데이터 딕셔너리에는 네 가지를 반드시 기록합니다. 항목명은 한글과 영문 이름을 모두 정해서 데이터를 식별할 수 있게 하고, 데이터 타입은 숫자인지 문자열인지 날짜인지 형식을 지정하며, 단위는 원, 억 원, %, %p처럼 정확히 명시하고, 정의 설명은 이 항목이 무엇을 의미하는지 한 문장으로 적어둡니다. 화면의 예시를 보시면, "전월대비증감률"이라는 항목이 소수점 1자리의 숫자 타입이고, 단위는 %이며, "전월 대비 이번 달 수치의 증감 비율"이라는 정의를 갖는다는 것을 한눈에 알 수 있습니다. 이렇게 만들어진 데이터 딕셔너리는 자동화 시스템 전체가 참고하는 공통 약속이 되어서, 나중에 어떤 담당자가 시스템을 수정하더라도 항상 같은 기준으로 데이터를 다룰 수 있게 해줍니다.

### 페이지 15. 항목별 데이터 타입, 단위, 형식 표준 지정

표준화가 필요한 대표 항목

- 금액: 억 원 단위로 통일, 소수점 첫째 자리까지 표기
- 비율: %(퍼센트)와 %p(퍼센트포인트) 명확히 구분하여 표기
- 날짜: YYYY-MM-DD 형식으로 통일
- 지역명, 기관명: 약칭이 아닌 공식 명칭으로 통일 (예: 서울을 서울특별시로)

> **[Note]** 데이터 딕셔너리를 만들 때 특히 자주 표기가 흔들리는 네 가지 항목을 콕 짚어서 표준을 정해두겠습니다. 첫째, 금액은 억 원 단위로 통일하고 소수점 첫째 자리까지 표기합니다. 둘째, 비율은 퍼센트(%)와 퍼센트포인트(%p)를 명확하게 구분해서 표기합니다. 이 둘을 헷갈리면 보도자료에 치명적인 오류가 생길 수 있다는 것은 1차시에서도 강조했던 내용입니다. 셋째, 날짜는 연-월-일(YYYY-MM-DD) 형식으로 통일합니다. 넷째, 지역명이나 기관명은 "서울"처럼 약칭으로 쓰지 않고 "서울특별시"처럼 공식 명칭으로 통일합니다. 같은 항목이라도 표기 방식이 다르면 AI가 문장을 만들 때 일관성이 깨질 수 있기 때문에, 이렇게 미리 표준을 정해두면 어떤 통계 자료가 들어와도 같은 규칙으로 자동 변환할 수 있는 기반이 마련됩니다.

### 페이지 16. 보도자료 작성용 데이터 항목 체크리스트 완성

항목 정의 완료 점검표

1. 모든 핵심 지표에 고유한 항목명이 부여되었는가
2. 필수, 선택, 참고 항목으로 우선순위가 구분되었는가
3. 항목별 데이터 타입과 단위가 명시되었는가
4. 데이터 딕셔너리 문서가 별도로 작성되어 관리되는가
5. 표기 형식(금액, 비율, 날짜 등)이 전사적으로 통일되었는가

> **[Note]** 이번 소주제를 마무리하면서, 데이터 항목 정의 작업이 제대로 되었는지 확인하는 다섯 가지 체크리스트를 소개하겠습니다. 첫째, 모든 핵심 지표에 고유한 항목명이 부여되었는지, 둘째, 필수·선택·참고 항목으로 우선순위가 구분되었는지, 셋째, 항목별 데이터 타입과 단위가 명시되었는지, 넷째, 데이터 딕셔너리 문서가 별도로 작성되어 관리되는지, 다섯째, 금액이나 비율, 날짜 같은 표기 형식이 전사적으로 통일되었는지를 점검합니다. 이 데이터 항목 정의 작업은 한 번 제대로 만들어두면 앞으로 진행할 2차시부터 10차시까지의 모든 실습에서 반복적으로 활용되는 기초 자산이 됩니다. 이제 이 체크리스트를 기준으로 삼아서, 다음 소주제부터는 실제 텍스트를 정제하고 표준화하는 구체적인 방법을 배워보겠습니다.

### 페이지 18. 텍스트 정제(Cleaning)의 개념과 필요성

정제가 필요한 대표 사례

- 불필요한 공백, 줄바꿈, 특수문자 제거
- 중복된 문장이나 반복 표현 제거
- 오탈자, 띄어쓰기 오류 교정
- 정제되지 않은 원본 텍스트를 AI에 그대로 입력하면 문맥 이해 오류 및 불필요한 토큰 낭비 발생

> **[Note]** 이제 비정형 텍스트를 실제로 다루는 세 가지 핵심 작업, 정제·표준화·구조화를 순서대로 배워보겠습니다. 먼저 정제입니다. 원본 자료에는 보고서를 PDF에서 추출할 때 생기는 깨진 문자, 불필요하게 중복된 줄바꿈이나 공백, 문서 앞뒤에 반복되는 머리말과 꼬리말 같은 요소들이 자주 섞여 있습니다. 이런 요소들을 제거하는 작업을 텍스트 정제라고 부릅니다. 정제가 왜 중요하냐면, 이런 불필요한 요소가 섞인 텍스트를 그대로 AI에게 입력하면 AI가 문맥을 잘못 이해할 수도 있고, 쓸데없이 많은 토큰을 낭비하게 되어 비용도 늘어납니다. 그래서 정제는 AI에게 텍스트를 전달하기 전에 반드시 거쳐야 하는 첫 번째 필수 단계입니다.

### 페이지 19. 표준화(Normalization) 원칙, 단위와 표기 통일

표준화 적용 규칙 예시

- 숫자 표기 통일: 1,000과 1000 중 콤마 포함 형식으로 통일
- 단위 표기 통일: 억원, 억 원, 100,000,000원 중 억 원으로 통일
- 날짜 표기 통일: 2026.1.1과 2026-01-01 중 하나의 형식으로 통일
- 전각, 반각 문자, 특수기호 표기 방식 통일

> **[Note]** 정제가 끝나면 다음은 표준화입니다. 같은 의미를 가진 내용이라도 표기 방식이 다르면 컴퓨터는 이것을 서로 다른 데이터로 인식해 버립니다. 예를 들어 "1,000"과 "1000"은 사람 눈에는 같아 보여도 문자열로는 다르고, "억원", "억 원", "100,000,000원"도 모두 같은 값이지만 표기가 다릅니다. 날짜도 "2026.1.1"과 "2026-01-01"처럼 여러 방식이 섞여 있으면 프로그램이 날짜로 인식하지 못할 수 있습니다. 그래서 표준화 단계에서는 숫자는 콤마를 포함한 형식으로, 금액 단위는 "억 원"으로, 날짜는 하이픈을 쓰는 형식으로 하나씩 규칙을 정해서 통일합니다. 이렇게 표준화를 해두면 이후 수치 계산과 AI 문장 생성 모두의 정확도가 높아지는 기반이 마련됩니다.

### 페이지 20. 구조화(Structuring), 비정형 텍스트를 정형 데이터로 변환

구조화 변환 절차

1. 원본 비정형 문서(보고서, 기사 등) 확보
2. 정제(Cleaning)를 통한 불필요 요소 제거
3. 표준화(Normalization)를 통한 표기 방식 통일
4. 항목별로 데이터 분리 및 라벨링
5. JSON 등 표준 형식으로 구조화하여 저장

> **[Note]** 정제와 표준화까지 마친 텍스트에 이제 마지막으로 구조화 작업을 적용합니다. 구조화란 항목별로 나누어 이름표를 붙이는 과정입니다. 절차를 보면, 먼저 원본 비정형 문서를 확보하고, 정제로 불필요한 요소를 제거하고, 표준화로 표기 방식을 통일한 다음, 항목별로 데이터를 분리해서 라벨을 붙이고, 마지막으로 JSON 같은 표준 형식으로 저장합니다. 예를 들어 보고서 속 문장에서 "총거래액은 201,250억 원이다"라는 표현을 찾았다면, 이 숫자를 "총거래액"이라는 항목명과 함께 분리해서 저장하는 것입니다. 이 과정을 거치면 비정형 텍스트가 비로소 프로그램이 자유롭게 다룰 수 있는 구조화된 데이터로 완전히 탈바꿈하게 됩니다.

### 페이지 21. 정제 전후 비교로 보는 품질 차이

정제 전

정제 후
```
2026년 1월 온라인쇼핑 거래액은 201,250억 원으로 전월 대비 1.5% 증가하였다.
```

개선 포인트: 중복 공백 제거, 단위 표기 통일(억원을 억 원으로), 불필요한 괄호 주석 제거, 문장 종결 표현 정리

> **[Note]** 지금까지 배운 정제와 표준화가 실제로 어떤 차이를 만드는지 예시로 직접 비교해 보겠습니다. 정제 전 문장을 보시면, 단어 사이사이에 불규칙한 공백이 여러 개 들어가 있고, "억원"처럼 띄어쓰기가 안 된 단위 표기가 있고, "(주:잠정치)"라는 불필요한 괄호 주석도 섞여 있습니다. 이 문장을 정제하고 표준화하면, 공백이 하나로 정리되고, "억 원"으로 단위 표기가 통일되고, 괄호 주석은 제거되며, 문장도 "~하였다"라는 자연스러운 종결 표현으로 다듬어집니다. 이렇게 정제된 문장은 AI가 문맥을 훨씬 명확하게 파악할 수 있게 해주고, 결과적으로 더 자연스럽고 정확한 보도자료 문장을 생성하는 밑거름이 됩니다.

### 페이지 22. 정제, 표준화, 구조화 통합 파이프라인 설계

통합 처리 파이프라인 구조

1. 원본 데이터(정형과 비정형)
2. 텍스트 정제 모듈 (공백, 오탈자, 중복 제거)
3. 표준화 모듈 (단위, 날짜, 숫자 형식 통일)
4. 구조화 모듈 (항목별 라벨링 및 JSON 변환)
5. 표준 데이터(JSON), 다음 단계(AI 분석, 작성)로 전달

> **[Note]** 지금까지 하나씩 배운 정제, 표준화, 구조화라는 세 가지 작업은 사실 순서대로 이어지는 하나의 파이프라인입니다. 정형 데이터와 비정형 데이터가 함께 원본으로 들어오면, 먼저 텍스트 정제 모듈이 공백과 오탈자, 중복을 제거하고, 그다음 표준화 모듈이 단위와 날짜, 숫자 형식을 통일하고, 마지막으로 구조화 모듈이 항목별로 라벨을 붙여 JSON으로 변환합니다. 이 파이프라인을 통과한 데이터는 원본이 정형이었든 비정형이었든 관계없이 항상 동일한 표준 구조로 정리되어서, 이후 AI가 안정적으로 분석하고 문장을 작성할 수 있는 튼튼한 기반이 됩니다. 이제 이 파이프라인 전체를 실제로 어떻게 파이썬 함수 하나로 구현하는지, 다음 페이지에서 직접 코드로 보여드리겠습니다.

### 페이지 23. Python 코드, clean_and_structure 함수 구현

```python
import re

def clean_and_structure(raw: dict) -> dict:
    """API 원본 응답 + 비정형 원문(raw['원문'])을 표준 JSON 구조로 변환한다."""
    text = raw.get("원문", "")

    # 1. 정제(Cleaning): 중복 공백, 괄호 주석 제거
    text = re.sub(r"\s+", " ", text).strip()
    text = re.sub(r"\(주:[^)]*\)", "", text)

    # 2. 표준화(Normalization): 단위 표기 통일(억원 -> 억 원)
    text = re.sub(r"(\d)억원", r"\1억 원", text)
    text = re.sub(r"(\d)백만원", r"\1백만 원", text)

    # 3. 구조화(Structuring): 표준 필드로 라벨링
    표준데이터 = {
        "문서정보": {
            "제목": raw.get("제목", ""),
            "공표일자": raw.get("공표일자", ""),
            "자료출처": raw.get("자료출처", "공공데이터포털 Open API"),
        },
        "계산지표": raw.get("계산지표", {}),
        "핵심내용": raw.get("핵심내용", []),
        "원문": text,
    }
    return 표준데이터
```

> **[Note]** 지금까지 배운 정제·표준화·구조화 원칙을 실제로 동작하는 파이썬 함수 하나로 만든 것이 바로 이 clean_and_structure 함수입니다. 이 함수는 raw라는 딕셔너리를 입력받는데, 여기에는 원문 텍스트와 함께, 이미 계산되어 있는 계산지표나 핵심내용 같은 값들이 함께 들어옵니다. 먼저 정규표현식으로 원문의 중복 공백을 하나로 합치고 괄호 주석을 제거하는 정제 작업을 수행하고, 이어서 "억원"을 "억 원"으로 바꾸는 표준화 작업을 적용합니다. 마지막으로 문서정보, 계산지표, 핵심내용, 원문이라는 네 가지 이름표를 가진 표준 데이터 구조로 정리해서 반환합니다. 여기서 중요한 점은, 이 함수는 이미 계산되어 들어온 계산지표 값은 그대로 재배치만 할 뿐 직접 계산하지는 않는다는 것입니다. 실제 증감률 계산은 5차시에서 만들 add_calculated_indicators라는 별도 함수가 담당하게 됩니다. 이 함수는 이후 10차시의 전체 파이프라인에서 가장 먼저 호출되는 관문 역할을 하므로, 오늘 그 원리를 정확히 이해해 두는 것이 중요합니다.

### 페이지 27. API 요청, 응답 구조 이해하기

API 통신 기본 구조

- 요청 URL: 데이터를 요청할 주소 (예: https://api.data.go.kr/openapi/...)
- 요청 파라미터: 인증키, 조회 기간, 데이터 형식(JSON, XML) 등 옵션 지정
- 응답 데이터: 요청이 성공하면 서버가 JSON 또는 XML 형태로 결과 반환

예시 요청 파라미터

```json
{
  "serviceKey": "발급받은_인증키",
  "startDate": "2026-01",
  "endDate": "2026-01",
  "resultType": "json"
}
```

> **[Note]** 인증키를 발급받았다면, 이제 이 키로 실제 API를 어떻게 호출하는지 그 구조를 이해해 보겠습니다. API 통신은 크게 세 가지로 구성됩니다. 첫째, 요청 URL은 데이터를 요청할 주소입니다. 둘째, 요청 파라미터는 인증키, 조회 기간, 그리고 결과를 JSON으로 받을지 XML로 받을지 같은 옵션을 지정하는 부분입니다. 셋째, 이 요청이 성공하면 서버가 JSON이나 XML 형태로 결과를 응답 데이터로 돌려줍니다. 화면의 예시처럼 serviceKey, startDate, endDate, resultType 같은 파라미터를 딕셔너리 형태로 준비해서 요청을 보내면 됩니다. 다만 한 가지 미리 말씀드리면, 실제로 여러분이 신청해서 승인받는 API마다 요청 파라미터의 이름과 형식, 그리고 응답이 JSON인지 XML인지가 조금씩 다를 수 있습니다. 그래서 API를 사용하기 전에는 반드시 활용신청 페이지에 첨부된 "활용가이드" 문서를 먼저 확인하는 습관을 들이는 것이 중요합니다.

### 페이지 28. Python requests 라이브러리로 실시간 데이터 수집 실습

API 호출 실습 코드

```python
import requests
import os
from dotenv import load_dotenv

load_dotenv()
SERVICE_KEY = os.getenv("PUBLIC_API_KEY")

url = "https://api.data.go.kr/openapi/tn_pubr_public_online_shopping_api"
params = {
    "serviceKey": SERVICE_KEY,
    "startDate": "2026-01",
    "endDate": "2026-01",
    "resultType": "json"
}

response = requests.get(url, params=params)
data = response.json()
print(data)
```

> **[Note]** 지금까지 배운 내용을 실제 파이썬 코드로 실행해 보겠습니다. requests 라이브러리를 이용하면 이렇게 몇 줄만으로 공공 API에 데이터를 요청하고 응답을 받아올 수 있습니다. 인증키는 코드에 직접 쓰지 않고 os.getenv 함수로 .env 파일에서 안전하게 불러오고, 응답 결과는 response.json() 함수로 곧바로 파이썬이 다룰 수 있는 딕셔너리 형태로 변환됩니다. 실습을 진행하시다 보면 실제 API마다 몇 가지 차이를 만날 수 있는데, 미리 알아두면 당황하지 않으실 겁니다. 첫째, 어떤 API는 응답을 JSON이 아니라 XML로 주기도 합니다. 이럴 때는 response.json() 대신 파이썬 표준 라이브러리인 xml.etree.ElementTree로 파싱해야 합니다. 둘째, 공공데이터포털은 인증키를 "인코딩"과 "디코딩" 두 형태로 제공하는데, requests가 파라미터 값을 스스로 한 번 더 인코딩하기 때문에 이미 인코딩된 키를 그대로 쓰면 이중 인코딩되어 인증 오류가 날 수 있습니다. 이럴 때는 urllib.parse.unquote() 함수로 먼저 한 번 디코딩해서 사용하면 안전합니다. 셋째, 조회 기간의 날짜 형식이나 최대 조회 가능 기간도 API마다 다를 수 있으므로, 활용가이드 문서의 요청변수 설명을 꼭 확인해야 합니다. 이런 실전 노하우까지 반영한 코드는 scripts 폴더의 공공 API 연동 스크립트에서 확인하실 수 있습니다.

### 페이지 29. 수집한 데이터를 표준 구조(JSON)로 저장하기

원본 응답에서 표준 구조로 변환하는 절차

1. API 원본 응답(JSON) 수신
2. 앞서 정의한 데이터 딕셔너리 항목명에 맞춰 필드명 매핑
3. 단위, 날짜 표기 표준화 규칙 적용
4. 표준 JSON 구조로 로컬 파일(data/raw_YYYYMM.json)에 저장

> **[Note]** API로 데이터를 받아왔다고 해서 바로 사용할 수 있는 것은 아닙니다. 기관마다 필드명과 형식이 제각각이기 때문입니다. 그래서 마지막 단계로, API 원본 응답을 받으면 앞서 우리가 만든 데이터 딕셔너리의 항목명에 맞춰 필드명을 다시 매핑하고, 단위와 날짜 표기에 표준화 규칙을 적용한 다음, 표준 JSON 구조로 로컬 파일에 저장합니다. 이렇게 한번 표준화 규칙을 만들어두면, 이후 어떤 통계 자료가 새로 들어오더라도 동일한 방식으로 처리할 수 있게 됩니다. 오늘 완성한 이 표준 데이터 구조가 바로 다음 3차시부터 시작될 자연어 처리 실습, 그리고 이후 이어지는 모든 차시의 공통 출발점이 된다는 것을 꼭 기억해 주시고, 이것으로 2차시를 마치겠습니다.
